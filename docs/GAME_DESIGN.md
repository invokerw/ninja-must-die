# 《影刃疾行》游戏设计文档

> Godot 4.x 横版跑酷动作游戏设计基线
>
> 文档版本：0.10 · 状态：首领流程及首轮音效、粒子与冲击反馈已实现并通过原型回归
>
> 本版在约 90 秒跑酷与首领流程上加入 21 个合成音效、金色碎屑、受击 / 击破冲击，以及独立开关。画面震动不移动实际镜头或碰撞体，固定方向并排齐射继续保留。七套自动回归通过，图形模式验证实际播放、暂停与结算音；存档、正式图片、手柄和移动端仍属后续范围。详细规则见 [角色技能设计](CHARACTER_SKILL_DESIGN.md)、[远程威胁](RANGED_THREATS.md)、[小型首领](BOSS_ENCOUNTER.md) 与 [音效与反馈](FEEDBACK.md)。

## 1. 项目概述

### 1.1 一句话描述

玩家操控一名在崩坏城域中沿单根钢索高速前进的忍者，在钢索上下翻转、跳跃并使用共享影步躲避机关，利用角色专属的冷却制主动技能与被动能力选择通过路线，收集“影晶”取得评分，最终击败首领或抵达终点。

### 1.2 产品定位

- **类型**：横版 2D/2.5D 跑酷 + 轻动作 + 关卡挑战
- **目标平台**：先完成 Windows 垂直切片，再适配 Android；后续可扩展到 iOS
- **引擎**：Godot 4.x，GDScript 为主
- **单局时长**：普通关卡 2～4 分钟，首领关 5～8 分钟
- **目标玩家**：喜欢短局、反应操作和重复挑战的玩家
- **核心体验**：高速、可预判、连续操作带来的爽感
- **美术方向**：原创东方幻想风，使用水墨轮廓、低饱和环境色和高亮技能特效；不复用其他作品的角色、名称、UI、素材或关卡设计

### 1.3 设计目标

1. 玩家在 10 秒内理解自动奔跑、钢索上下翻转和闪避。
2. 30 秒内出现一次需要判断时机的障碍组合。
3. 操作失误可归因，失败后能快速重试。
4. 同一关卡通过熟练度产生“更快、更稳、更高连击”的成长感。
5. 首个可玩版本只依赖少量资源，也能验证核心循环。

### 1.4 非目标

- 首个版本不做开放世界、多人联机、抽卡和复杂基地经营。
- 不在原型阶段同时支持大量角色、武器和宠物。
- 不追求一次性做完整剧情；剧情以短文本和过场占位为主。

### 1.5 原型阶段的范围锁定

- 核心移动面只有一根横向钢索。角色始终沿 X 轴自动前进，在钢索上方和下方两种附着状态之间切换。
- 钢索上按 `drop` 翻到钢索下方；钢索下按 `jump` 翻回上方。钢索下重复按或长按 `drop` 保持附着，不触发松绳。钢索上按 `jump` 可跳离钢索，下落时自动落回钢索上方；接近钢索时也允许手动重新抓绳。
- 首个关卡使用手工编排的固定段落，不做程序随机生成。随机段落等核心循环稳定后再加入。
- 评分只评价一次通关结果，永久成长和装备系统不参与首个垂直切片。
- 每名角色固定一个主动和一个被动；主动走冷却，施放后提供短时无敌，不消耗影能。基础二段跳，首名角色由被动提升至三段跳。
- 移除近身普通斩击；影晶与击破只影响收集、连击和评分，不改变技能可用性。

## 2. 核心玩法

### 2.1 玩家循环

```text
选择关卡 → 自动前进 → 判断路线 → 位移/闪避/攻击 → 收集影晶
    ↑                                         ↓
结算评级 ← 击败首领或抵达终点 ← 使用技能处理危险段
```

每次失败都保留已解锁内容，玩家可以立即重试。关卡评价由通关时间、受击次数、收集率和连击表现共同决定。

### 2.2 三个核心支柱

| 支柱 | 玩家行为 | 设计要求 |
| --- | --- | --- |
| 读图 | 识别障碍位于钢索上方还是下方，并提前翻转 | 障碍在屏幕内提前显示；上下侧使用统一形状、颜色和音效提示 |
| 节奏 | 在上/下翻转、跳离、重新抓绳和影步之间连续衔接 | 翻转时间短且有明确锁定，动作之间允许短暂取消，避免输入被吞 |
| 复盘 | 记住障碍侧别、跳跃落点和失败位置 | 结算页记录失败原因；重试加载时间目标小于 2 秒 |

### 2.3 关卡中的基本交互

- **自动奔跑**：角色沿 X 轴持续前进，玩家主要决定钢索侧别、空中轨迹和短时间位移。
- **钢索翻转**：在钢索上按下键翻到下方，在钢索下按跳跃键翻回上方。翻转后进入短暂锁定，避免同一帧来回抖动。
- **跳离钢索**：钢索上按跳跃键离开钢索向上跳；基础二段跳，具备“踏影”被动时可三段跳。下落时脚部从上方穿过钢索便自动落回钢索上方，无需再次按键；落绳后按角色被动刷新跳跃次数并清除已缓冲输入。
- **下侧保持附着**：下键只负责翻到钢索下方；已经在下方时，连按或长按下键都保持当前身位并继续前进。避开下侧障碍时按跳跃键翻回上方。
- **影步**：短距离无敌冲刺，可穿过部分攻击和窄缝；在钢索上使用时保持当前侧别。
- **角色主动与被动**：每名角色固定一个主动技能和一个自动生效的被动。主动通过冷却恢复，释放后提供无敌保护；不设置近身普通攻击和影能消耗。
- **收集**：普通影晶分布在钢索上下两侧的角色身位内，翻到对应一侧并保持附着即可直接收集。路线通过侧别切换和机关时机产生取舍。

### 2.4 钢索侧别与连击规则

- 每个危险段先明确目标侧别：障碍从钢索向上伸展时，推荐玩家翻到下侧；障碍从钢索向下伸展时，推荐玩家翻到上侧。连续障碍可以要求上下快速交替。
- 障碍入口、钢索支架、收集物和终点提示必须在同一屏幕内可见；不能用镜头外信息迫使玩家盲猜。
- 普通影晶必须处于钢索附着姿态的身体范围内，且与伤害机关保持间隔；下侧无法直接触及的位置不放影晶。奖励只影响收集率、连击和评分，不提升伤害或缩短技能冷却。
- 当前连击在击败敌人或收集影晶时增加，连续 2 秒没有有效事件或受到伤害时归零；无伤穿越危险段的连击奖励留待后续加入。
- 连击只影响结算分数和 HUD 反馈，不改变钢索碰撞判定和关卡必通条件。

## 3. 操作方案

### 3.1 输入映射

| Action 名称 | 键盘 | 手柄 | 触屏 | 说明 |
| --- | --- | --- | --- | --- |
| `jump` | W / ↑ / Space | A / 南键 | 左侧跳跃按钮 | 钢索下翻回上方；钢索上跳离钢索；按角色额度追加空中跳跃，或接近钢索时重新抓绳 |
| `drop` | S / ↓ | 左摇杆下 | 左侧下翻按钮 | 钢索上翻到下方；钢索下保持附着；空中加速下落 |
| `dash` | Shift | X / 西键 | 右侧冲刺按钮或横滑 | 影步，带无敌帧 |
| `skill` | K / 鼠标右键 | Y / 北键 | 右侧技能按钮 | 释放角色主动技能，使用后冷却；长按不自动重复 |
| `pause` | Esc | Menu | 双指点击 | 暂停 |

建议使用 Godot InputMap 管理 Action，不在脚本中直接判断具体键值。触屏输入只负责映射为同一套 Action。移动端原型优先使用固定虚拟按钮，滑动手势作为可选增强，避免高速场景中手势识别不稳定。按钮旁应显示当前语义，例如钢索上显示“下翻”，钢索下显示“上翻”。

### 3.2 操作容错

- 跳跃输入预缓冲：离开钢索前后 0.12 秒内的输入可在有效状态到达时执行。
- 自动落绳：比较本次物理移动前后的角色脚部位置，只在下落并从上方穿过钢索时吸附；高速下落跨过钢索也不能漏判，上升经过时不自动吸附。
- 手动重新抓绳窗口：角色下落至钢索中心线前后 42 px 内，按跳跃可抓回上方钢索，作为近绳空中状态的补救操作。
- 下键容错：钢索下重复按或长按下键均保持附着，不改变高度、不触发坠落，也不阻止后续上翻。
- 翻转锁定：上/下翻转后锁定 0.10 秒，只锁定再次翻转，不锁定影步和必要的失败判定。
- 影步结束后保留 0.05 秒输入锁，避免连续冲刺抖动。
- 角色受伤后 0.8 秒无敌，避免连续碰撞导致不可控死亡。
- 钢索翻转会播放 0.24 秒的压缩和金色弧光反馈；反馈只改变视觉，不延长翻转锁定时间。

### 3.3 信息反馈

- HUD 右上角显示距离终点的百分比进度，帮助玩家建立本段关卡的空间预期。
- HUD 同时显示下一处机关的目标侧别和按当前跑速估算的到达时间；机关进入约 420 px 预警距离后，在钢索旁显示脉冲式金色指示。
- 预警只提示已经进入玩家视野和反应窗口的机关，不替代障碍本体的上下侧形状和碰撞判定。

## 4. 角色与战斗设计

### 4.1 玩家基础参数（原型值）

| 参数 | 值 | 备注 |
| --- | ---: | --- |
| 自动跑速 | 320 px/s | 关卡可在 260～420 px/s 范围调整 |
| 钢索中心线 | 520 px | 当前控制切片的世界 Y 坐标 |
| 钢索侧别偏移 | 34 px | 角色身体中心到钢索中心线的距离 |
| 跳跃初速度 | -680 px/s | 使用重力模拟抛物线 |
| 重力 | 1800 px/s² | 需要配合关卡节奏微调 |
| 二段跳高度 | 一段跳的 65% | 二段跳后不能再次刷新 |
| 基础最大跳跃段数 | 2 | 一段起跳 + 一次空中跳；被动可增加至 3 |
| 踏影第三段初速度 | -500 px/s | 仅有该被动的角色生效 |
| 影步距离 | 180 px | 0.18 秒内完成 |
| 影步无敌 | 0.18 秒 | 共享位移，沿用原型值 |
| 影步冷却 | 0.35 秒 | 结束后才允许再次使用 |
| 钢索翻转锁定 | 0.10 秒 | 防止上下输入抖动 |
| 重新抓绳窗口 | 42 px | 下落穿过钢索附近按跳跃可抓回 |
| 生命值 | 3 | 受击减少 1，归零失败 |
| 连击衰减 | 2 秒 | 没有有效事件时归零 |
| 月蚀斩冷却 | 12 秒 | 当前配置，成功释放时开始计时 |
| 月蚀斩无敌 | 2 秒 | 当前配置，输入被接受时立即生效 |

### 4.2 玩家状态机

```text
ROPE_TOP ── drop ──> ROPE_BOTTOM
ROPE_BOTTOM ── jump ──> ROPE_TOP
ROPE_BOTTOM ── drop ──> ROPE_BOTTOM（保持附着）
ROPE_TOP ── jump ──> JUMP_1
JUMP_1 ── jump ──> JUMP_2 ── jump（仅踏影）──> JUMP_3
任意跳跃段 ── 下降 ──> FALL ── 从上方落到钢索（自动）──> ROPE_TOP
FALL ── jump（手动抓绳窗口）──> ROPE_TOP
所有可行动状态 ── dash / hit / fail ──> 对应状态
```

`DASH` 是叠加在钢索或空中的短时状态；`STOPPED` 用于结算和暂停。状态切换必须集中在 `PlayerStateMachine` 中，动画、碰撞箱和输入只读取当前状态，避免在多个脚本中互相修改速度。

主动技能的冷却与无敌独立于移动状态计时，不强制进入会锁住翻绳或跳跃的移动状态；技能和影步均不刷新空中跳跃次数。

### 4.3 敌人分类

- **地面哨兵**：固定位置巡逻，适合教学躲避与技能时机。
- **飞行追猎者**：从屏幕外进入，迫使玩家使用跳跃或影步。
- **盾卫**：拥有可预警的防御阶段，需要躲避或在暴露弱点时使用主动技能；留待后续评估。
- **投射手**：发射可预判弹道，负责制造纵向节奏。
- **精英敌人**：拥有一条可读的攻击循环，作为首领前的压力测试。

敌人只拥有少量高辨识度行为。每个行为都需要明确的预警阶段、攻击阶段和恢复阶段。

已有 5 个 **悬浮哨兵** 固定在钢索一侧的身体高度，1 点生命、接触伤害 1，可用主动技能击破，或翻绳、跳跃与影步避开。另有 2 次 **屏幕右侧远程来袭**：发射源悬浮在右边缘外 48 px，位置按实际屏幕、镜头和窗口尺寸计算；不占钢索位置、不造成接触伤害，也不参与击破计分。屏内三条平行金线预警 0.8 秒后，每波 3 枚飞弹以 720 px/s 从画外同向并排射入。方向由关卡预先配置，不瞄准玩家；中心间距 144 px，留出翻绳和跳跃的躲避间隙。子弹经过玩家后继续飞出画面，每枚只结算一次接触。技能、影步与受伤无敌均有效。入门段保留纯移动教学。详见 [投射物与远程威胁](RANGED_THREATS.md)。

移除普通斩击后，敌人布置必须允许不用技能安全躲避；不把冷却未结束变成必定受伤的条件。

### 4.4 角色主动技能

每名角色固定一个主动技能。首名角色“影刃”的主动为 **月蚀斩**，当前实现参数如下：

- 12 秒冷却，开局与重试时就绪；成功释放即开始冷却，不要求影能、收集或命中。
- 释放当帧开始提供 2 秒无敌，免疫伤害但不修正坠落轨迹；独立于受伤与影步保护，不累计时长，也不被较短保护覆盖。
- 0.12 秒视觉蓄势后结算一次攻击；保持自动奔跑、翻绳和跳跃可用，移除旧版停顿与 0.8 秒释放锁定。
- 对前方 640 px、纵向上下各 100 px 范围内敌人造成 3 点伤害，一次释放对每个敌人最多命中一次。附着时以钢索为纵向中心，空中以出招时身体高度为中心。
- 普通机关不会被清除；无敌时可以安全接触，通过后机关仍保留。
- 冷却中或无效状态的按键不施放；空放有效；长按不会在技能就绪时自动施放。

冷却与无敌使用可配置的秒数，暂停时冻结。本轮先验证 12 / 2 秒，不将数值作为全部后续角色的固定值。

### 4.5 角色被动与跳跃段数

基础二段跳包含一段起跳与一次空中跳跃。首名角色“影刃”的被动为 **踏影**，额外增加一次空中跳跃，成为三段跳；其他被动不自动获得第三段。

钢索下按跳跃只上翻，不消耗起跳段数；只有实际落绳或成功手动抓绳才刷新额度。技能、影步、受击和收集物均不刷新。第三段后不能继续第四段，长按不自动连跳。

角色开局前确定，本局内不切换；每名角色恰好一个主动和一个被动，当前先实现影刃。详细参数、边界、HUD、资源结构和迁移验收见 [角色主动技能与被动能力设计](CHARACTER_SKILL_DESIGN.md)。

## 5. 关卡设计

### 5.1 关卡结构

每个关卡由若干可复用的“节拍段”组成，每段长度约 8～16 秒。每段都要标注障碍目标侧别和可选跳跃路线：

1. **安全段**：让玩家恢复节奏、收集资源。
2. **教学段**：只引入一个新障碍，先让玩家在一侧安全翻转。
3. **组合段**：把上下障碍组合成连续翻转和短暂跳离。
4. **压力段**：加入敌人或连续机关。
5. **奖励段**：风险更高但提供额外影晶/卷轴。
6. **首领段**：追逐时让首领保持在玩家前方，使用单阶段、三种可预警攻击循环。

### 5.2 原型关卡：雾岭断桥（完整展示关卡目标）

- **主题**：夜间山谷中的断桥和浮空石台
- **目标时长**：约 90 秒
- **目标速度下的长度**：约 28,800 px（按 320 px/s 计算）
- **节拍段数量**：8～10 段，单段 8～16 秒
- **解锁条件**：初始开放
- **节奏**：钢索教学 → 上下交替障碍 → 跳跃与自动落绳 → 飞行追猎者 → 钢索冲刺 → 小型首领
- **必需元素**：单根钢索、上下两侧尖刺/落石、影晶、1 种普通敌人、1 种投射物、单阶段小型首领、终点门
- **评价目标**：
  - C：完成关卡
  - B：用时不超过 130 秒，受击不超过 2 次
  - A：用时不超过 110 秒，收集率至少 70%，受击不超过 1 次
  - S：用时不超过 90 秒，收集率至少 80%，全程无受击

评级顺序固定为 S>A>B>C；若同时满足多个等级，取最高等级。计时从角色获得控制权开始，到首领死亡或通过终点门时结束。

#### 5.2.1 已有 60 秒路线与新技能验收

已有原型提供一条 60 秒路线。基础跑速 320 px/s，总长度 19,200 px；起点 X=160，终点 X=19,360，影步会缩短实际通关时间。v0.7 已保留布局并替换战斗与角色规则。

| 时间 | 段落 | 机关 / 影晶 | 体验目标 |
| --- | --- | --- | --- |
| 0～10 秒 | 钢索入门 | 3 / 7 | 稀疏机关和可达影晶引导上下翻绳 |
| 10～25 秒 | 上下交替 | 7 / 14 | 稳定交替翻绳，按安全侧收集 |
| 25～45 秒 | 连续机关 | 13 / 18 | 同侧成组与异侧交替，可选择跳跃跨越 |
| 45～60 秒 | 冲刺收尾 | 6 / 11 | 间距缩短，影步可选，最后约 5 秒奖励与收尾 |

- 全部 29 个机关可以通过翻绳无伤避开，50 个影晶可在附着状态收齐。
- 单跳、二段跳跨越与影步穿越作为基础可选路线；三段跳提供额外补救，不能成为主路线或普通影晶的强制要求。
- 段落按角色世界坐标切换；HUD 常驻显示段落名称、顺序与对应操作提示，影步加速后不会错过分段切换。
- 钢索、背景、相机边界、终点进度及评级基准统一读取关卡资源，避免延长关卡后出现镜头截断或旧评级阈值。
- 当前评级使用基础时长 +1/+10/+25 秒对应 S/A/B，分别要求受击 0/≤1/≤2 次、收集率 ≥90%/≥65%/≥35%。击破数和最高连击增加总分，不作为高评级的必通条件。
- v0.7 已回放四条完整路线：基础二段跳配置的纯翻绳、二段跳 / 影步，以及影刃的冷却技能、三段跳 / 快速落绳 / 影步 / 技能。均无伤收齐 50 个影晶；实际时长分别为 59.88 / 59.50 / 59.88 / 59.50 秒，技能路线各击破 3 个哨兵。另验证暂停、重开、下侧终点和终点取消待结算攻击。

#### 5.2.2 v0.9 首领流程

默认主场景在上述路线末端接入单阶段首领“断桥机关鸢”。登场 1.5 秒后，按上侧横扫、下侧横扫、三重平射循环；每次预警 1.2 秒，生效 0.45 秒，收招开放弱点 2.6 秒。9 点生命需要三次月蚀斩有效命中，护甲期间仍可获得技能保护但不造成伤害。飞弹保持屏幕右侧外发射、固定方向、并排留隙与完整飞行。

所有首领攻击都能靠普通翻绳避开，玩家可以等待技能冷却后再攻击。击破后记入击破与连击，退场 0.65 秒后结算；完整流程评级基准为 90 秒，两条完整回放约 89.3～89.6 秒，均无伤收齐 50 个影晶并取得 S。`scenes/practice.tscn` 保留原 60 秒路线，`scenes/boss_practice.tscn` 可直接练习首领。详见 [小型首领](BOSS_ENCOUNTER.md)。

### 5.3 障碍设计规范

每个障碍资源至少包含：

- 预警时长
- 有效碰撞形状
- 伤害值
- 是否可被角色主动技能破坏；当前尖刺不可破坏
- 是否受影步穿越影响
- 目标钢索侧别（`top` / `bottom`）和从钢索中心线延伸的高度
- 触发后的音效和粒子
- 调试用颜色和标签

当前控制切片额外提供统一的接近预警：障碍距玩家 420 px 内显示金色脉冲指示，HUD 用“上侧/下侧 + 秒数”重复表达同一信息。预警距离按当前 320 px/s 跑速约等于 1.3 秒，后续调整跑速时应同步调整该值。

障碍必须在玩家反应窗口内出现。普通障碍建议提前 0.7～1.2 秒可见，首领攻击建议提前 0.9～1.5 秒预警。编辑器中的预警距离按 `recommended_speed × warning_time` 计算，避免关卡换速后危险元素突然贴脸。

### 5.4 影晶摆放规范

- 普通影晶的中心高度绑定角色附着时的身体中心：`rope_y - side × rope_offset`。当前钢索上侧为 Y=486、下侧为 Y=554，随角色身位参数一起调整。
- 影晶图形必须处于对应侧角色的身体高度范围内；钢索下的影晶通过下翻后保持附着即可收集，不能超出身位、要求松绳下坠。无法满足时取消该处下侧影晶。
- 收集判定保持正常接触范围，普通影晶不得跨钢索被另一侧角色收走。
- 影晶不能与机关碰撞区域重叠；放在机关之后时，为角色留出通过机关和切换侧别的空间。
- 验收使用实际关卡中的所有影晶：角色在正确侧保持附着前进即可收集；错误侧不会收集，收集过程中不会受伤或坠落。

### 6.2.1 Autoload 边界

只将跨场景且确实需要持久化的服务设为 Autoload：

| Autoload | 职责 |
| --- | --- |
| `Game` | 场景切换、全局暂停和运行模式 |
| `SaveData` | 版本化存档读写 |
| `AudioManager` | 音乐、音效总线和音量设置 |

`RunSession`、`LevelController` 和玩家都属于关卡实例，不设为 Autoload，避免重试时残留旧状态。

### 6.3 脚本职责

| 模块 | 职责 | 不应负责 |
| --- | --- | --- |
| `RunSession` | 当前局状态、计时、收集和结算 | 播放具体动画 |
| `PlayerController` | 读取输入、提交意图、驱动状态机 | 直接控制敌人 |
| `PlayerStateMachine` | 状态切换、状态生命周期 | 保存永久成长数据 |
| `LevelController` | 关卡滚动、节拍段生成、终点 | 处理 UI 布局 |
| `SegmentSpawner` | 根据关卡数据实例化段落 | 判断玩家受伤 |
| `Hitbox/Hurtbox` | 统一伤害检测和反馈 | 修改关卡进度 |
| `SaveData` | 读写本地存档 | 持有运行时临时状态 |
| `HUDController` | 显示生命、角色能力、技能冷却、计时和提示 | 直接修改玩家属性 |

`RunResult` 使用独立的轻量数据类保存 `time_seconds`、`damage_count`、`collectible_count`、`collectible_total`、`max_combo` 和 `rank`，由 `RunSession` 生成后传给结算界面，避免 HUD 重新计算成绩。`checkpoint_reached` 在原型阶段只用于调试标记和后续扩展，失败仍从关卡起点重试。

使用信号解耦模块，例如：

```gdscript
signal player_damaged(amount: int)
signal skill_cooldown_changed(remaining: float, total: float)
signal run_finished(result: RunResult)
signal checkpoint_reached(index: int)
```

### 6.4 数据资源

优先使用 `Resource` 保存可调参数，避免把平衡数值散落在脚本中。

```gdscript
class_name LevelSegmentData
extends Resource

@export var segment_id: StringName
@export var scene: PackedScene
@export var length_px: float = 1600.0
@export var recommended_speed: float = 320.0
@export var difficulty: int = 1
@export var tags: Array[StringName] = []
@export var warning_time: float = 0.9
@export var route_type: StringName = &"safe"
```

角色、敌人、技能和障碍都采用相同思路，运行时只负责读取数据并执行行为。`.tres` 资源只保存配置，不在运行时直接修改；运行时状态放在实例脚本中。

当前实现使用 `RopeLevelData` → `RopeSegmentData` → `RopeHazardData` / `RopePickupData` / `RopeEnemyData` 资源，入口为 `data/levels/fog_ridge_60s.tres`。机关、影晶和敌人的横坐标相对段落起点；影晶和敌人高度绑定角色附着身位。

`RopeLevelController` 负责数据校验、实例生成、分段通知及钢索绘制；主场景 `Level` 节点及其子节点均可暂停，`main.gd` 负责局内计时、输入和 HUD。异侧危险物（机关或敌人）至少保留 0.75 秒翻绳窗口，影晶与同侧危险物扣除碰撞半宽后至少间隔 80 px；校验覆盖段落边界。

v0.7 的 `Player/Combat` 中，`RunnerCombat` 已改为管理主动技能、冷却、命中记录、连击和击破统计，删除普通斩击与影能分支。角色由 `CharacterData` 引用一个 `ActiveSkillData` 和一个 `PassiveData`；跳跃额度由共享基础段数与角色被动计算。`RunResult` 保留原评分；局内状态不写回 `.tres`，重开重新创建。

完整编辑步骤与资源字段见 `data/levels/README.md`。通关回放位于 `tests/test_level_route.gd`，原有落绳和影晶碰撞测试继续保留。

## 7. 碰撞与物理约定

建议在项目设置中固定以下碰撞层：

| 层 | 名称 | 用途 |
| ---: | --- | --- |
| 1 | World | 地面、墙体、平台 |
| 2 | Player | 玩家身体 |
| 3 | Enemy | 敌人身体 |
| 4 | PlayerHitbox | 玩家攻击范围 |
| 5 | EnemyHitbox | 敌人攻击范围 |
| 6 | Pickup | 影晶、卷轴 |
| 7 | Trigger | 检查点、终点、生成触发器 |
| 8 | Destructible | 可被角色技能破坏的物件（预留） |

玩家身体使用 `CharacterBody2D`，攻击和受击使用独立 `Area2D`。玩家身体只与 `World` 碰撞；玩家受击箱监听 `EnemyHitbox`；玩家攻击箱监听 `Enemy` 和 `Destructible`。伤害判断由 `Hurtbox` 接收信号，避免让敌人脚本直接访问玩家生命值。

原型沿用较小实现：哨兵与首领是 `Enemy` 层的 `Area2D`，主动技能使用物理空间矩形查询并保持每次施放的命中记录；首领只在收招弱点期间接受伤害。机关使用独立伤害层，不会被月蚀斩破坏。飞弹以圆形、首领横扫以矩形对玩家实际碰撞形状做相对运动扫掠，共用 `PlayerController.take_damage()`；不额外注册物理层。无敌只阻止伤害结算，不关闭拾取或入口碰撞；有效技能输入先于同帧伤害结算。

## 8. 镜头、滚动与生成

- 使用 `Camera2D` 跟随一个独立的 `CameraRig`，玩家在屏幕左侧约 35% 位置。
- 关卡沿 X 轴生成，摄像机前方至少保留 1.5 个屏幕宽度的预加载内容。
- 当段落尾端离开摄像机后回收，避免无限关卡产生节点增长。
- 生成器只依赖 `LevelSegmentData`，可在编辑器中替换段落顺序。
- 首领追逐段解除原跑酷终点的镜头右边界，首领保持在玩家前方；背景和钢索随追逐进度延伸，直到击破后结算。
- 世界坐标以玩家 X 位置为唯一前进基准，不同时使用“移动玩家”和“移动世界”两套速度。生成器在摄像机前方至少 `1.5 × viewport_width` 生成内容，在摄像机后方一个屏幕后回收。

## 9. UI 与反馈

### 9.1 HUD

显示生命、时间、收集数、角色名称与被动、钢索侧别、连击和主动技能冷却。技能区显示 `K`、技能名、就绪高亮或剩余秒数；移除 `J` 提示与影能条。无敌期间显示保护光圈与剩余时长，结束前 0.35 秒收拢提示；空中显示剩余追加跳跃次数。钢索翻转保留已有侧别反馈。

### 9.2 反馈优先级

1. 角色是否受伤或死亡
2. 是否成功执行位移
3. 技能是否可用
4. 是否获得收集物
5. 连击与评级变化

每次重要事件至少提供两种反馈，例如颜色闪烁 + 音效，避免只依赖文字。

v0.10 已为实际位移、拾取、技能、预警、受击、护甲接触、首领动作与结算接入短音效；粒子使用当局固定容量绘制，画面震动使用 HUD 下方的屏幕采样处理，不改物理坐标。`F2` 打开设置，`M` 静音，音效、粒子、震动与冲击闪光可以独立关闭，偏好跨重试保留于本次程序运行。详细事件、资源来源、混音与暂停规则见 [音效与反馈](FEEDBACK.md)。

### 9.3 UI 与资源图片生成规范

所有 UI 视觉素材和游戏资源图片统一使用图片生成工具制作，默认采用内置 `imagegen` 工作流。生成结果必须经过人工检查后才能进入 Godot；最终使用的文件必须复制到项目内，不能只保存在工具的默认输出目录。控制切片阶段允许使用代码绘制的临时占位图形验证碰撞和节奏，但占位图形不得作为正式资源发布。

#### 9.3.1 生成范围

适合使用图片生成工具的内容：

- 角色、敌人、首领和 NPC 的立绘、动作参考图、透明背景精灵。
- 关卡背景、远景、中景、装饰物、机关和可破坏物。
- UI 面板底图、按钮底图、图标、徽章、技能图形和装饰纹理。
- 技能特效、保护光圈、烟雾、火花、技能斩光残影和奖励光效。

UI 的布局、动态文字、数值、计时器和交互状态使用 Godot `Control` 节点实现。图片生成工具只负责视觉素材，避免把不可缩放的文字和按钮状态直接烘焙进位图。

#### 9.3.2 统一视觉基线

项目建立一个风格锚点文件：`art/style_guide/style_anchor.png`。后续生成的图片都以该文件作为风格参考，并在提示词中明确保持以下特征：

- 原创东方幻想、水墨轮廓、手绘笔触、2D 横版游戏资产。
- 低饱和蓝灰和雾紫作为环境主色，朱砂红作为危险/攻击强调色，暖金色作为奖励和技能高光。
- 柔和月光、薄雾层次、清晰剪影、适度留白；避免写实摄影、厚重 3D 渲染和高饱和卡通风。
- 统一的光源方向：左上方月光，角色和道具的高光方向保持一致。
- 角色和敌人的轮廓必须在深色背景上清楚可辨，危险元素拥有统一的朱砂红边缘光。

建议色板：墨夜 `#111827`、雾蓝 `#34495E`、远景灰 `#6E7F8D`、朱砂 `#B24B4B`、暖金 `#D8B56A`、月光 `#DDE7E7`。色板用于生成提示词、Godot UI 主题和后处理，不要求每张图片逐像素匹配。

#### 9.3.3 生成流程

1. 先生成风格锚点和一张角色/场景基准图，确认线条、色板、光向和细节密度。
2. 为每类资产固定构图模板：角色三视图/动作图、敌人正侧面、背景横向 16:9、UI 图标正面居中。
3. 每次生成使用统一提示词结构：用途、主体、场景、媒介风格、构图、光照、色板、材质、透明度和避用项。
4. 同一批资源保持相同的风格锚点、画幅比例、镜头高度和光源方向；只改变主体和动作。
5. 生成后检查轮廓、透明边缘、色差、重复纹理、UI 可读性和是否出现文字/水印；不合格图片只做单项修改后重新生成。
6. 通过检查后导入 Godot，再在目标分辨率和移动端预览中确认缩放效果。

#### 9.3.4 提示词模板

每个资源保存一份同名 `.prompt.md`，记录生成依据和后续迭代内容。统一使用以下模板：

```text
Use case: <game asset / ui-mockup / stylized-concept>
Asset type: <character / enemy / environment / UI panel / icon / effect>
Primary request: <主体和用途>
Input images: style_anchor.png as style reference
Scene/backdrop: <场景或透明背景>
Subject: <主体、姿态、数量>
Style/medium: original oriental fantasy, ink outline, hand-painted 2D game asset
Composition/framing: <横版构图、正面/侧面、留白和比例>
Lighting/mood: soft moonlight from upper left, readable silhouette
Color palette: ink night, mist blue, muted purple, cinnabar red, warm gold
Materials/textures: <纸张、水墨、金属、木材或布料>
Text (verbatim): ""  # 资源图默认不生成文字
Constraints: consistent with style_anchor.png, clean edges, production-ready
Avoid: watermark, logo, readable text, random extra objects, photorealism, 3D render
```

## 10. 存档与结算

### 10.1 当前结算

通关后显示用时、受击次数、影晶数 / 总数、击破数、最高连击、总分和评级。评分为：

`总分 = 1000 通关分 + 时间奖励 + 无伤奖励 + 影晶数 ×20 + 击破数 ×150 + 最高连击 ×10`

时间奖励为 `round(1000 × min(基础时长 / 实际用时, 1))`；无伤时奖励 500 分。评级 S/A/B 按第 5.2 节的时间、受击和收集率门槛判定，其余通关为 C。结算、暂停均有全屏压暗，重试清空本局战斗统计。

## 11. 垂直切片范围

### 11.1 必做内容

- 1 名玩家角色，配一个主动技能与一个被动能力
- 1 个 90 秒关卡，包含一根连续钢索
- 自动奔跑、钢索上/下翻转、下侧稳定附着、跳离钢索、基础二段跳、踏影三段跳、自动落绳、重新抓绳、影步
- 1 种普通敌人、1 种投射物、4 种上下侧障碍、1 个单阶段小型首领
- 生命、角色主动技能冷却与无敌、被动、收集物、结算评级
- 固定段落、侧别提示、连击和 S/A/B/C 评级
- 暂停、重试、存档
- 键盘输入和基础手柄输入

首领只实现 3 种可预警攻击、1 个阶段和明确的死亡结算，不制作完整演出或多阶段变身。若实现资源不足，首领可以降级为“终点波次”，但必须保留一次完整的战斗结算。

### 11.2 暂不做

- 多角色和角色养成
- 复杂装备、宠物和抽取系统
- 在线排行榜
- 多人模式
- 全剧情和高质量配音

### 11.3 垂直切片验收标准

1. 新玩家不看说明能在 60 秒内完成一次上翻、下翻、跳离钢索和影步。
2. 玩家能在钢索上下两侧连续通过至少 6 个交替障碍，失败后可以一键重试。
3. 普通跳跃和二段跳后无需额外输入即可自动落回钢索，长按跳跃不会在落绳后自动再跳；钢索下连按或长按下键保持附着，随后按跳跃键仍能正常翻回上方。
4. 普通障碍的目标侧别、预警时间和碰撞结果稳定，无明显穿模或误伤。
5. 运行 10 分钟不出现节点数量持续增长或输入失灵。
6. Windows 1080p 目标保持 60 FPS；Android 首个适配目标保持 30 FPS，性能良好设备再提升到 60 FPS；帧率下降不能改变判定结果。
7. 小型首领的 3 种攻击都能在预警阶段辨识，击败后能正确进入结算。

### 11.4 分层验收顺序

为避免在钢索手感未稳定前投入首领和内容制作，按以下顺序验收：

1. **控制切片（20～30 秒）**：单根钢索自动奔跑、上/下翻转、稳定附着、跳离、自动落绳、重新抓绳、影步、交替侧别障碍和一键重试；不包含敌人、首领和存档。
2. **玩法切片（60～90 秒）**：加入收集物、普通敌人、冷却制主动技能、被动、评分和结算。
3. **展示切片（完整关卡）**：加入单阶段小型首领、音效、粒子、存档和性能验证。

只有上一层满足验收标准后才进入下一层；如果翻转锁定、重新抓绳窗口或碰撞判定仍在调整，应暂停内容扩展。

## 13. 测试清单

### 功能测试

- 钢索上按 `drop` 能翻到下方，钢索下按 `jump` 能翻回上方。
- 钢索上按 `jump` 能离开钢索；钢索下连按或长按 `drop` 始终保持附着、身位高度和自动前进，随后按 `jump` 能翻回上方。
- 普通跳跃、二段跳和空中快速下落均能自动落回钢索，无需再次按 `jump`；高速跨越落绳位置不会穿透。
- 上升经过钢索不会自动落绳。
- 空中下落接近钢索并按 `jump` 能手动重新抓绳；手动抓绳超出 42 px 窗口不会错误吸附。
- 关卡中的普通影晶在对应侧保持附着即可收集，钢索下侧不会出现超过身位的影晶；另一侧不能隔绳收集。
- 翻转锁定期间不会连续切换侧别；影步和受伤无敌时间正确。
- 角色受伤、死亡、重试和结算状态不会重复触发。
- 关卡重载后生成顺序、收集数量和计时正确。
- 60 秒路线可无伤收齐 50 个影晶；四段教学提示按位置依次触发，影步不会打乱顺序。
- 相机、钢索和终点覆盖完整关卡；上下两侧通过终点均能结算，进度达到 100%。
- `J` 不触发攻击，界面无影能条；收集和击破不改变技能冷却。
- 月蚀斩开局就绪，冷却 12 秒、无敌 2 秒；有效施放同帧建立保护，空放有效，长按与冷却中的输入不重复触发。
- 技能保持自动前进和移动输入，不刷新跳跃额度；钢索下释放时保持附着，攻击不清除普通机关。
- 基础配置最多二段跳，踏影最多三段跳；上翻不计起跳，实际落绳 / 抓绳才恢复额度。
- 无敌阻止扣血、受击统计和连击中断，但不干扰收集、终点与坠落失败；不同无敌来源不累加或互相缩短。
- 连击 2 秒无事件或受击时中断，最高连击保留；暂停冻结冷却与无敌，重试技能就绪并清除旧局状态。
- 基础二段跳无技能路线、三段跳与冷却技能路线均已完整回放，终点锁定成绩后不再补结算技能攻击。

### 体验测试

- 第一次失败时玩家能理解失败原因。
- 连续操作时没有明显输入吞键。
- 不同屏幕宽高比下，障碍不会在出现前直接进入碰撞范围。
- 音效、闪烁和屏幕震动可单独关闭。

### 性能测试

- 运行 10 分钟后场景节点数量保持稳定。
- 生成和回收段落时无明显卡顿。
- 大量粒子同时出现时仍维持目标帧率。

### 开发调试工具

- 一键重载当前关卡，并支持从任意节拍段开始。
- 显示碰撞箱、当前状态、段落 ID、玩家速度和帧耗时。
- 提供无敌、跳过首领、时间倍率（0.25x/0.5x/1x）和固定种子选项。
- 调试开关只在开发构建可用，不能写入正式存档。

## 14. 后续扩展方向

当垂直切片稳定后，再按优先级扩展：

1. 3 个新关卡和 1 个正式首领。
2. 第二名角色，复用同一关卡系统但改变技能节奏。
3. 挑战模式：无伤、限时、收集和随机段落。
4. 装备词条或轻量成长，只影响路线选择，不破坏基础操作公平性。
5. 移动端手势优化、震动反馈和云存档。
6. 在钢索核心稳定后，再评估“短跳/滑步”速度技：它可以作为高阶路线表达，但不能削弱上下翻转的基础可读性。

任何扩展都应先回答：它是否增加路线判断、操作表达或复盘价值；若只增加数值复杂度，应延后。
