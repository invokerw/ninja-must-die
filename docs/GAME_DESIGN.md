# 《影刃疾行》游戏设计文档

> Godot 4.x 横版跑酷动作游戏设计基线
>
> 文档版本：0.3 · 状态：钢索控制切片可验收

## 1. 项目概述

### 1.1 一句话描述

玩家操控一名在崩坏城域中沿单根钢索高速前进的忍者，在钢索上方与下方之间翻转、跳离、重新抓绳并使用影步躲避机关，通过收集“影晶”积攒技能，最终击败关卡首领并解锁新的挑战。

### 1.2 产品定位

- **类型**：横版 2D/2.5D 跑酷 + 轻动作 + 关卡挑战
- **目标平台**：先完成 Windows 垂直切片，再适配 Android；后续可扩展到 iOS
- **引擎**：Godot 4.x，GDScript 为主
- **单局时长**：普通关卡 2～4 分钟，首领关 5～8 分钟
- **目标玩家**：喜欢短局、反应操作和重复挑战的玩家
- **核心体验**：高速、可预判、连续操作带来的爽感
- **美术方向**：原创东方幻想风，使用水墨轮廓、低饱和环境色和高亮技能特效；不复用其他作品的角色、名称、UI、素材或关卡设计

### 1.3 设计目标

1. 玩家在 10 秒内理解自动奔跑、钢索上下翻转和闪避。
2. 30 秒内出现一次需要判断时机的障碍组合。
3. 操作失误可归因，失败后能快速重试。
4. 同一关卡通过熟练度产生“更快、更稳、更高连击”的成长感。
5. 首个可玩版本只依赖少量资源，也能验证核心循环。

### 1.4 非目标

- 首个版本不做开放世界、多人联机、抽卡和复杂基地经营。
- 不在原型阶段同时支持大量角色、武器和宠物。
- 不追求一次性做完整剧情；剧情以短文本和过场占位为主。

### 1.5 原型阶段的范围锁定

- 核心移动面只有一根横向钢索。角色始终沿 X 轴自动前进，在钢索上方和下方两种附着状态之间切换。
- 钢索上按 `drop` 翻到钢索下方；钢索下按 `jump` 翻回上方。钢索上按 `jump` 可跳离钢索，钢索下按 `drop` 可松绳下落；空中接近钢索时允许重新抓绳。
- 首个关卡使用手工编排的固定段落，不做程序随机生成。随机段落等核心循环稳定后再加入。
- 评分只评价一次通关结果，永久成长和装备系统不参与首个垂直切片。

## 2. 核心玩法

### 2.1 玩家循环

```text
选择关卡 → 自动前进 → 判断路线 → 位移/闪避/攻击 → 收集影晶
    ↑                                         ↓
结算评级 ← 击败首领或抵达终点 ← 使用技能处理危险段
```

每次失败都保留已解锁内容，玩家可以立即重试。关卡评价由通关时间、受击次数、收集率和连击表现共同决定。

### 2.2 三个核心支柱

| 支柱 | 玩家行为 | 设计要求 |
| --- | --- | --- |
| 读图 | 识别障碍位于钢索上方还是下方，并提前翻转 | 障碍在屏幕内提前显示；上下侧使用统一形状、颜色和音效提示 |
| 节奏 | 在上/下翻转、跳离、重新抓绳和影步之间连续衔接 | 翻转时间短且有明确锁定，动作之间允许短暂取消，避免输入被吞 |
| 复盘 | 记住障碍侧别、松绳落点和失败位置 | 结算页记录失败原因；重试加载时间目标小于 2 秒 |

### 2.3 关卡中的基本交互

- **自动奔跑**：角色沿 X 轴持续前进，玩家主要决定钢索侧别、空中轨迹和短时间位移。
- **钢索翻转**：在钢索上按下键翻到下方，在钢索下按跳跃键翻回上方。翻转后进入短暂锁定，避免同一帧来回抖动。
- **跳离钢索**：钢索上按跳跃键离开钢索向上跳；空中可追加一次二段跳。接近钢索并按跳跃可重新抓回上方钢索。
- **松绳下落**：钢索下按下键松开钢索向下掉落，用于避开连续下侧障碍或进入下方奖励区；掉落过深会失败。
- **影步**：短距离无敌冲刺，可穿过部分攻击和窄缝；在钢索上使用时保持当前侧别。
- **斩击与技能**：战斗系统沿用自动奔跑框架，斩击处理近距离敌人，技能消耗影能处理压力段。
- **收集**：影晶分布在钢索上方或下方，收集路线必须让玩家承担可读的侧别风险。

### 2.4 钢索侧别与连击规则

- 每个危险段先明确目标侧别：障碍从钢索向上伸展时，推荐玩家翻到下侧；障碍从钢索向下伸展时，推荐玩家翻到上侧。连续障碍可以要求上下快速交替。
- 障碍入口、钢索支架、收集物和终点提示必须在同一屏幕内可见；不能用镜头外信息迫使玩家盲猜。
- 奖励物可以放在危险侧或松绳路径上，但奖励只影响收集率和影能，不直接提升伤害。
- 连击在击败敌人、无伤穿越危险段或收集奖励物时增加，连续 2 秒没有有效事件或受到伤害时归零。
- 连击只影响结算分数和 HUD 反馈，不改变钢索碰撞判定和关卡必通条件。

## 3. 操作方案

### 3.1 输入映射

| Action 名称 | 键盘 | 手柄 | 触屏 | 说明 |
| --- | --- | --- | --- | --- |
| `jump` | W / ↑ / Space | A / 南键 | 左侧跳跃按钮 | 钢索下翻回上方；钢索上跳离钢索；空中二段跳或接近钢索时重新抓绳 |
| `drop` | S / ↓ | 左摇杆下 | 左侧下滑或下落按钮 | 钢索上翻到下方；钢索下松绳下落 |
| `dash` | Shift | X / 西键 | 右侧冲刺按钮或横滑 | 影步，带无敌帧 |
| `attack` | J / 鼠标左键 | RB | 右侧攻击按钮 | 斩击 |
| `skill` | K / 鼠标右键 | Y / 北键 | 右侧技能按钮或长按 | 消耗影能 |
| `pause` | Esc | Menu | 双指点击 | 暂停 |

建议使用 Godot InputMap 管理 Action，不在脚本中直接判断具体键值。触屏输入只负责映射为同一套 Action。移动端原型优先使用固定虚拟按钮，滑动手势作为可选增强，避免高速场景中手势识别不稳定。按钮旁应显示当前语义，例如钢索上显示“下翻”，钢索下显示“上翻”。

### 3.2 操作容错

- 跳跃输入预缓冲：离开钢索前后 0.12 秒内的输入可在有效状态到达时执行。
- 重新抓绳窗口：角色下落穿过钢索中心线前后 42 px 内，按跳跃可抓回上方钢索。
- 翻转锁定：上/下翻转后锁定 0.10 秒，只锁定再次翻转，不锁定影步和必要的失败判定。
- 影步结束后保留 0.05 秒输入锁，避免连续冲刺抖动。
- 角色受伤后 0.8 秒无敌，避免连续碰撞导致不可控死亡。

## 4. 角色与战斗设计

### 4.1 玩家基础参数（原型值）

| 参数 | 值 | 备注 |
| --- | ---: | --- |
| 自动跑速 | 320 px/s | 关卡可在 260～420 px/s 范围调整 |
| 钢索中心线 | 520 px | 当前控制切片的世界 Y 坐标 |
| 钢索侧别偏移 | 34 px | 角色身体中心到钢索中心线的距离 |
| 跳跃初速度 | -680 px/s | 使用重力模拟抛物线 |
| 重力 | 1800 px/s² | 需要配合关卡节奏微调 |
| 二段跳高度 | 一段跳的 65% | 二段跳后不能再次刷新 |
| 影步距离 | 180 px | 0.18 秒内完成 |
| 影步无敌 | 0.18 秒 | 首领攻击可设置穿透例外 |
| 影步冷却 | 0.35 秒 | 结束后才允许再次使用 |
| 钢索翻转锁定 | 0.10 秒 | 防止上下输入抖动 |
| 重新抓绳窗口 | 42 px | 下落穿过钢索附近按跳跃可抓回 |
| 生命值 | 3 | 受击减少 1，归零失败 |
| 影能上限 | 100 | 影晶每个恢复 10 |
| 斩击伤害 | 1 | 普通敌人 1～3 点生命 |
| 连击衰减 | 2 秒 | 没有有效事件时归零 |
| 技能释放锁定 | 0.8 秒 | 月蚀斩结束后恢复输入 |

### 4.2 玩家状态机

```text
ROPE_TOP ── drop ──> ROPE_BOTTOM
   │                    │
 jump                jump
   │                    │
   ▼                    ▼
JUMP → DOUBLE_JUMP → FALL ── jump（抓绳窗口）──> ROPE_TOP
   │                    │
   └──── dash / hit / fail（所有可行动状态均可进入）
ROPE_BOTTOM ── drop ──> FALL（松绳）
```

`DASH` 是叠加在钢索或空中的短时状态；`STOPPED` 用于结算和暂停。状态切换必须集中在 `PlayerStateMachine` 中，动画、碰撞箱和输入只读取当前状态，避免在多个脚本中互相修改速度。

### 4.3 敌人分类

- **地面哨兵**：固定位置巡逻，适合教学斩击。
- **飞行追猎者**：从屏幕外进入，迫使玩家使用跳跃或影步。
- **盾卫**：正面免疫普通斩击，需要绕后或使用技能。
- **投射手**：发射可预判弹道，负责制造纵向节奏。
- **精英敌人**：拥有一条可读的攻击循环，作为首领前的压力测试。

敌人只拥有少量高辨识度行为。每个行为都需要明确的预警阶段、攻击阶段和恢复阶段。

### 4.4 技能原型

首个垂直切片只实现一个技能：**月蚀斩**。

- 消耗 100 影能；首个版本不设置独立冷却，使用 0.8 秒释放锁定避免连续触发。
- 角色短暂停顿 0.12 秒，随后在屏幕前方生成横向斩击。
- 对普通敌人造成高伤害，对首领造成固定百分比伤害。
- 播放期间角色获得 0.25 秒无敌。
- 技能结束后恢复自动奔跑，不改变关卡滚动位置。

后续技能可以复用 `Ability` 基类，增加护盾、减速或范围爆破。

## 5. 关卡设计

### 5.1 关卡结构

每个关卡由若干可复用的“节拍段”组成，每段长度约 8～16 秒。每段都要标注障碍目标侧别和是否允许松绳：

1. **安全段**：让玩家恢复节奏、收集资源。
2. **教学段**：只引入一个新障碍，先让玩家在一侧安全翻转。
3. **组合段**：把上下障碍组合成连续翻转和短暂跳离。
4. **压力段**：加入敌人或连续机关。
5. **奖励段**：风险更高但提供额外影晶/卷轴。
6. **首领段**：固定镜头或半固定镜头，使用单阶段、三种可预警攻击循环。

### 5.2 原型关卡：雾岭断桥

- **主题**：夜间山谷中的断桥和浮空石台
- **目标时长**：约 90 秒
- **目标速度下的长度**：约 28,800 px（按 320 px/s 计算）
- **节拍段数量**：8～10 段，单段 8～16 秒
- **解锁条件**：初始开放
- **节奏**：钢索教学 → 上下交替障碍 → 松绳与重新抓绳 → 飞行追猎者 → 钢索冲刺 → 小型首领
- **必需元素**：单根钢索、上下两侧尖刺/落石、影晶、1 种普通敌人、1 种投射物、单阶段小型首领、终点门
- **评价目标**：
  - C：完成关卡
  - B：用时不超过 130 秒，受击不超过 2 次
  - A：用时不超过 110 秒，收集率至少 70%，受击不超过 1 次
  - S：用时不超过 90 秒，收集率至少 80%，全程无受击

评级顺序固定为 S>A>B>C；若同时满足多个等级，取最高等级。计时从角色获得控制权开始，到首领死亡或通过终点门时结束。

### 5.3 障碍设计规范

每个障碍资源至少包含：

- 预警时长
- 有效碰撞形状
- 伤害值
- 是否可被斩击破坏
- 是否受影步穿越影响
- 目标钢索侧别（`top` / `bottom`）和从钢索中心线延伸的高度
- 触发后的音效和粒子
- 调试用颜色和标签

障碍必须在玩家反应窗口内出现。普通障碍建议提前 0.7～1.2 秒可见，首领攻击建议提前 0.9～1.5 秒预警。编辑器中的预警距离按 `recommended_speed × warning_time` 计算，避免关卡换速后危险元素突然贴脸。

### 6.2.1 Autoload 边界

只将跨场景且确实需要持久化的服务设为 Autoload：

| Autoload | 职责 |
| --- | --- |
| `Game` | 场景切换、全局暂停和运行模式 |
| `SaveData` | 版本化存档读写 |
| `AudioManager` | 音乐、音效总线和音量设置 |

`RunSession`、`LevelController` 和玩家都属于关卡实例，不设为 Autoload，避免重试时残留旧状态。

### 6.3 脚本职责

| 模块 | 职责 | 不应负责 |
| --- | --- | --- |
| `RunSession` | 当前局状态、计时、收集和结算 | 播放具体动画 |
| `PlayerController` | 读取输入、提交意图、驱动状态机 | 直接控制敌人 |
| `PlayerStateMachine` | 状态切换、状态生命周期 | 保存永久成长数据 |
| `LevelController` | 关卡滚动、节拍段生成、终点 | 处理 UI 布局 |
| `SegmentSpawner` | 根据关卡数据实例化段落 | 判断玩家受伤 |
| `Hitbox/Hurtbox` | 统一伤害检测和反馈 | 修改关卡进度 |
| `SaveData` | 读写本地存档 | 持有运行时临时状态 |
| `HUDController` | 显示生命、影能、计时和提示 | 直接修改玩家属性 |

`RunResult` 使用独立的轻量数据类保存 `time_seconds`、`damage_count`、`collectible_count`、`collectible_total`、`max_combo` 和 `rank`，由 `RunSession` 生成后传给结算界面，避免 HUD 重新计算成绩。`checkpoint_reached` 在原型阶段只用于调试标记和后续扩展，失败仍从关卡起点重试。

使用信号解耦模块，例如：

```gdscript
signal player_damaged(amount: int)
signal energy_changed(current: int, maximum: int)
signal run_finished(result: RunResult)
signal checkpoint_reached(index: int)
```

### 6.4 数据资源

优先使用 `Resource` 保存可调参数，避免把平衡数值散落在脚本中。

```gdscript
class_name LevelSegmentData
extends Resource

@export var segment_id: StringName
@export var scene: PackedScene
@export var length_px: float = 1600.0
@export var recommended_speed: float = 320.0
@export var difficulty: int = 1
@export var tags: Array[StringName] = []
@export var warning_time: float = 0.9
@export var route_type: StringName = &"safe"
```

角色、敌人、技能和障碍都采用相同思路，运行时只负责读取数据并执行行为。`.tres` 资源只保存配置，不在运行时直接修改；运行时状态放在实例脚本中。

## 7. 碰撞与物理约定

建议在项目设置中固定以下碰撞层：

| 层 | 名称 | 用途 |
| ---: | --- | --- |
| 1 | World | 地面、墙体、平台 |
| 2 | Player | 玩家身体 |
| 3 | Enemy | 敌人身体 |
| 4 | PlayerHitbox | 玩家攻击范围 |
| 5 | EnemyHitbox | 敌人攻击范围 |
| 6 | Pickup | 影晶、卷轴 |
| 7 | Trigger | 检查点、终点、生成触发器 |
| 8 | Destructible | 可被斩击破坏的机关 |

玩家身体使用 `CharacterBody2D`，攻击和受击使用独立 `Area2D`。玩家身体只与 `World` 碰撞；玩家受击箱监听 `EnemyHitbox`；玩家攻击箱监听 `Enemy` 和 `Destructible`。伤害判断由 `Hurtbox` 接收信号，避免让敌人脚本直接访问玩家生命值。

## 8. 镜头、滚动与生成

- 使用 `Camera2D` 跟随一个独立的 `CameraRig`，玩家在屏幕左侧约 35% 位置。
- 关卡沿 X 轴生成，摄像机前方至少保留 1.5 个屏幕宽度的预加载内容。
- 当段落尾端离开摄像机后回收，避免无限关卡产生节点增长。
- 生成器只依赖 `LevelSegmentData`，可在编辑器中替换段落顺序。
- 摄像机在首领段切换为固定边界，战斗结束后恢复滚动。
- 世界坐标以玩家 X 位置为唯一前进基准，不同时使用“移动玩家”和“移动世界”两套速度。生成器在摄像机前方至少 `1.5 × viewport_width` 生成内容，在摄像机后方一个屏幕后回收。

## 9. UI 与反馈

### 9.1 HUD

左上角显示生命；右上角显示影能、当前时间和收集数；中央或左上角显示当前钢索侧别（钢索上 / 钢索下 / 空中）；底部显示技能充能和连击；危险方向使用短时箭头提示。钢索翻转成功时显示短暂的侧别标签和音效。技能没有独立冷却，界面只显示影能是否达到 100 以及 0.8 秒释放锁定。

### 9.2 反馈优先级

1. 角色是否受伤或死亡
2. 是否成功执行位移
3. 技能是否可用
4. 是否获得收集物
5. 连击与评级变化

每次重要事件至少提供两种反馈，例如颜色闪烁 + 音效，避免只依赖文字。

### 9.3 UI 与资源图片生成规范

所有 UI 视觉素材和游戏资源图片统一使用图片生成工具制作，默认采用内置 `imagegen` 工作流。生成结果必须经过人工检查后才能进入 Godot；最终使用的文件必须复制到项目内，不能只保存在工具的默认输出目录。控制切片阶段允许使用代码绘制的临时占位图形验证碰撞和节奏，但占位图形不得作为正式资源发布。

#### 9.3.1 生成范围

适合使用图片生成工具的内容：

- 角色、敌人、首领和 NPC 的立绘、动作参考图、透明背景精灵。
- 关卡背景、远景、中景、装饰物、机关和可破坏物。
- UI 面板底图、按钮底图、图标、徽章、技能图形和装饰纹理。
- 技能特效、烟雾、火花、斩击残影和奖励光效。

UI 的布局、动态文字、数值、计时器和交互状态使用 Godot `Control` 节点实现。图片生成工具只负责视觉素材，避免把不可缩放的文字和按钮状态直接烘焙进位图。

#### 9.3.2 统一视觉基线

项目建立一个风格锚点文件：`art/style_guide/style_anchor.png`。后续生成的图片都以该文件作为风格参考，并在提示词中明确保持以下特征：

- 原创东方幻想、水墨轮廓、手绘笔触、2D 横版游戏资产。
- 低饱和蓝灰和雾紫作为环境主色，朱砂红作为危险/攻击强调色，暖金色作为奖励和技能高光。
- 柔和月光、薄雾层次、清晰剪影、适度留白；避免写实摄影、厚重 3D 渲染和高饱和卡通风。
- 统一的光源方向：左上方月光，角色和道具的高光方向保持一致。
- 角色和敌人的轮廓必须在深色背景上清楚可辨，危险元素拥有统一的朱砂红边缘光。

建议色板：墨夜 `#111827`、雾蓝 `#34495E`、远景灰 `#6E7F8D`、朱砂 `#B24B4B`、暖金 `#D8B56A`、月光 `#DDE7E7`。色板用于生成提示词、Godot UI 主题和后处理，不要求每张图片逐像素匹配。

#### 9.3.3 生成流程

1. 先生成风格锚点和一张角色/场景基准图，确认线条、色板、光向和细节密度。
2. 为每类资产固定构图模板：角色三视图/动作图、敌人正侧面、背景横向 16:9、UI 图标正面居中。
3. 每次生成使用统一提示词结构：用途、主体、场景、媒介风格、构图、光照、色板、材质、透明度和避用项。
4. 同一批资源保持相同的风格锚点、画幅比例、镜头高度和光源方向；只改变主体和动作。
5. 生成后检查轮廓、透明边缘、色差、重复纹理、UI 可读性和是否出现文字/水印；不合格图片只做单项修改后重新生成。
6. 通过检查后导入 Godot，再在目标分辨率和移动端预览中确认缩放效果。

#### 9.3.4 提示词模板

每个资源保存一份同名 `.prompt.md`，记录生成依据和后续迭代内容。统一使用以下模板：

```text
Use case: <game asset / ui-mockup / stylized-concept>
Asset type: <character / enemy / environment / UI panel / icon / effect>
Primary request: <主体和用途>
Input images: style_anchor.png as style reference
Scene/backdrop: <场景或透明背景>
Subject: <主体、姿态、数量>
Style/medium: original oriental fantasy, ink outline, hand-painted 2D game asset
Composition/framing: <横版构图、正面/侧面、留白和比例>
Lighting/mood: soft moonlight from upper left, readable silhouette
Color palette: ink night, mist blue, muted purple, cinnabar red, warm gold
Materials/textures: <纸张、水墨、金属、木材或布料>
Text (verbatim): ""  # 资源图默认不生成文字
Constraints: consistent with style_anchor.png, clean edges, production-ready
Avoid: watermark, logo, readable text, random extra objects, photorealism, 3D render
```

#### 9.3.5 文件与导入规范

生成文件按用途存放，并使用稳定命名：

```text
art/
├── style_guide/style_anchor.png
├── generated/
│   ├── characters/char_shadow_runner_v01.png
│   ├── enemies/enemy_flying_hunter_v01.png
│   ├── environments/env_fog_ridge_bg_v01.png
│   ├── ui/ui_panel_hud_v01.png
│   └── fx/fx_moon_slash_v01.png
└── prompts/
    └── <与资源同名>.prompt.md
```

- `v01`、`v02` 表示新版本，禁止无记录覆盖旧资源。
- 角色、敌人、特效和图标优先生成透明背景；背景图和面板底图使用不透明背景。
- UI 面板和背景优先生成 16:9 或可九宫格裁切的素材；图标保持正方形，主体占画布 70%～80%。
- 透明素材导入 Godot 时保留 Alpha；水墨边缘不能出现明显白边或黑边。
- 绘制风格素材使用线性过滤；像素级占位素材另行标记，不能混用两套过滤规则。

#### 9.3.6 资源验收标准

- 与 `style_anchor.png` 的线条、色板、光向和细节密度一致。
- 在 1080p 和 Android 目标分辨率下，角色、危险元素和按钮图标仍能快速辨识。
- UI 素材不包含不可修改的文字、数字、品牌标识和水印。
- 透明资源边缘干净，缩放、旋转和叠加后没有明显色边。
- 每个入库资源都有对应提示词文件、版本号、用途和尺寸记录。

  "best_times": {"level_01_fog_ridge": 93.4},
  "best_ranks": {"level_01_fog_ridge": "A"},

## 11. 垂直切片范围

### 11.1 必做内容

- 1 名玩家角色
- 1 个 90 秒关卡，包含一根连续钢索
- 自动奔跑、钢索上/下翻转、跳离钢索、二段跳、重新抓绳、松绳下落、影步
- 1 种普通敌人、1 种投射物、4 种上下侧障碍、1 个单阶段小型首领
- 生命、影能、收集物、结算评级
- 固定段落、侧别提示、连击和 S/A/B/C 评级
- 暂停、重试、存档
- 键盘输入和基础手柄输入

首领只实现 3 种可预警攻击、1 个阶段和明确的死亡结算，不制作完整演出或多阶段变身。若实现资源不足，首领可以降级为“终点波次”，但必须保留一次完整的战斗结算。

### 11.2 暂不做

- 多角色和角色养成
- 复杂装备、宠物和抽取系统
- 在线排行榜
- 多人模式
- 全剧情和高质量配音

### 11.3 垂直切片验收标准

1. 新玩家不看说明能在 60 秒内完成一次上翻、下翻、跳离钢索和影步。
2. 玩家能在钢索上下两侧连续通过至少 6 个交替障碍，失败后可以一键重试。
3. 空中下落接近钢索时按跳跃可以在重新抓绳窗口内回到钢索上方；超出窗口会按预期坠落。
4. 普通障碍的目标侧别、预警时间和碰撞结果稳定，无明显穿模或误伤。
5. 运行 10 分钟不出现节点数量持续增长或输入失灵。
6. Windows 1080p 目标保持 60 FPS；Android 首个适配目标保持 30 FPS，性能良好设备再提升到 60 FPS；帧率下降不能改变判定结果。
7. 小型首领的 3 种攻击都能在预警阶段辨识，击败后能正确进入结算。

### 11.4 分层验收顺序

为避免在钢索手感未稳定前投入首领和内容制作，按以下顺序验收：

1. **控制切片（20～30 秒）**：单根钢索自动奔跑、上/下翻转、跳离、松绳、重新抓绳、影步、交替侧别障碍和一键重试；不包含敌人、首领和存档。
2. **玩法切片（60～90 秒）**：加入收集物、普通敌人、斩击、影能、评分和结算。
3. **展示切片（完整关卡）**：加入单阶段小型首领、音效、粒子、存档和性能验证。

只有上一层满足验收标准后才进入下一层；如果翻转锁定、重新抓绳窗口或碰撞判定仍在调整，应暂停内容扩展。

## 12. 开发里程碑

### M0：项目骨架（1～2 天）

- 创建 Godot 项目、InputMap、目录和基础场景。
- 建立调试 HUD、碰撞层和日志入口。

### M1：可操作角色（3～5 天）

- 完成自动奔跑、钢索上/下翻转、跳离、重新抓绳、影步。
- 加入状态机、动画占位和相机跟随。

### M2：可玩路线（3～5 天）

- 完成钢索轨道、上下侧尖刺/落石、收集物和固定节拍段。
- 用占位图块拼出“雾岭断桥”。

### M3：战斗和结算（3～5 天）

- 完成斩击、敌人、伤害、月蚀斩、生命和失败流程。
- 完成单阶段小型首领的 3 种攻击、死亡和结算触发。
- 加入计时、收集率和评级。

### M4：打磨与验证（3～5 天）

- 添加音效、粒子、屏幕震动和基础 UI。
- 完成存档、重试、手柄适配、移动端虚拟按钮和性能检查。

## 13. 测试清单

### 功能测试

- 钢索上按 `drop` 能翻到下方，钢索下按 `jump` 能翻回上方。
- 钢索上按 `jump` 能离开钢索；钢索下按 `drop` 能松绳下落，超出边界会失败。
- 空中下落接近钢索并按 `jump` 能重新抓绳；超出 42 px 窗口不会错误吸附。
- 翻转锁定期间不会连续切换侧别；影步和受伤无敌时间正确。
- 角色受伤、死亡、重试和结算状态不会重复触发。
- 关卡重载后生成顺序、收集数量和计时正确。

### 体验测试

- 第一次失败时玩家能理解失败原因。
- 连续操作时没有明显输入吞键。
- 不同屏幕宽高比下，障碍不会在出现前直接进入碰撞范围。
- 音效、闪烁和屏幕震动可单独关闭。

### 性能测试

- 运行 10 分钟后场景节点数量保持稳定。
- 生成和回收段落时无明显卡顿。
- 大量粒子同时出现时仍维持目标帧率。

### 开发调试工具

- 一键重载当前关卡，并支持从任意节拍段开始。
- 显示碰撞箱、当前状态、段落 ID、玩家速度和帧耗时。
- 提供无敌、跳过首领、时间倍率（0.25x/0.5x/1x）和固定种子选项。
- 调试开关只在开发构建可用，不能写入正式存档。

## 14. 后续扩展方向

当垂直切片稳定后，再按优先级扩展：

1. 3 个新关卡和 1 个正式首领。
2. 第二名角色，复用同一关卡系统但改变技能节奏。
3. 挑战模式：无伤、限时、收集和随机段落。
4. 装备词条或轻量成长，只影响路线选择，不破坏基础操作公平性。
5. 移动端手势优化、震动反馈和云存档。
6. 在钢索核心稳定后，再评估“短跳/滑步”速度技：它可以作为高阶路线表达，但不能削弱上下翻转的基础可读性。

任何扩展都应先回答：它是否增加路线判断、操作表达或复盘价值；若只增加数值复杂度，应延后。
