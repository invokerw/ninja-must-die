# 角色模块与可更换武器设计

> 版本：0.2 · 日期：2026-10-25 · 状态：v0.11 已实现，已通过自动回放与图形检查
>
> 本文将武器纳入角色模块，补充 [首领战斗扩展](BOSS_COMBAT_DESIGN.md) 的装备、界面、数据和生命周期规则。当前运行版本为 v0.11，准备页、两种武器、装备存档与出战快照均已实现；数值仍可按真人试玩调整。

## 1. 角色的完整配置

每名角色由固有能力和当前装备共同组成：

```text
角色：影刃
├── 固有主动：月蚀斩（K）
├── 固有被动：踏影（三段跳）
└── 主武器槽：弦月轮 / 贯星矛（二选一）
    └── 武器技能（J，名称、行为与冷却跟随装备）
```

角色模块负责武器槽、可装备条件、装备选择和对外提供完整出战配置。角色的主动与被动由角色定义，当前武器由玩家选择。更换武器只替换 J 的能力和武器外观，不改变 K、跳跃段数、影步、生命或碰撞体。

武器定义独立复用：后续多个角色可以使用同一把武器，各自记住上次装备。拥有武器是本地玩家档案层面的解锁状态，不把一把武器永久占用给某个角色，也不因切换角色而消耗物品。首轮只有影刃，接口按每名角色一套装备记录设计。

首轮每名角色一个主武器槽。飞镖球是首领场内的攻击道具，不占槽，也不作为永久装备保存在角色上。角色仍然恰好一个固有主动、一个固有被动。

## 2. 两把起始武器

| 武器 | 技能表现与首领战基础值 | 使用特点 |
| --- | --- | --- |
| 弦月轮 `crescent_wheel` | 6 秒冷却，按下后在 0 / 0.12 / 0.24 秒各发一枚刃波，每枚基础伤害 4，总计 12 | 多段连续命中，补伤害频繁；跨越弱点结束时，后续刃波可能只吃护甲伤害 |
| 贯星矛 `star_lance` | 8 秒冷却，蓄势 0.30 秒后发出一枚长矛，单次基础伤害 16 | 单次命中更集中，需要把蓄势和飞行时间算进弱点窗口 |

两把武器的理论基础输出均为 2 点 / 秒，先用攻击节奏形成选择，不预设后一把全面强于前一把。护甲减伤后的整组伤害分别为 6 和 8；弱点开放时分别为 12 和 16。真实效率受飞行时间、漏击和施放时机影响，必须分别试玩。

两者首轮都默认解锁，无等级、稀有度、强化、词条或抽取流程。弦月轮是影刃的默认装备；贯星矛用于检验更换后行为、冷却、图标和说明是否完整跟随。两把均无无敌，不清除敌弹、不打断首领，也不赋予额外跳跃。

两种弹体都锁定当前首领，允许有限转向，并实际飞行、碰撞后结算伤害。弦月轮速度 1300 px/s、最大转向 6 rad/s，贯星矛 1600 px/s、最大转向 3 rad/s，两者弹体寿命均为 2 秒。速度与转向上限由各自资源配置；调试时应保证钢索上下侧的正常发射可靠命中，避免自动奔跑造成无意义空放。伤害取命中当帧的护甲倍率。

表内均为首领战数值。首轮武器技能只在首领正式交战状态启用，跑酷段显示“首领战启用”；原月蚀斩在跑酷段的伤害和使用规则继续沿用 v0.10。将武器推广到普通哨兵战之前，需另做关卡与伤害平衡。

## 3. 从角色界面更换

正常启动进入轻量的“角色与武器”准备页，作为正常启动入口：左侧展示当前角色、固有主动和被动，右侧展示已装备武器与可选武器卡，底部提供“完整关卡”“首领练习”“跑酷练习”。首轮直接显示影刃，不用未制作角色填充界面。

选中武器卡时先预览名称、图标、攻击演示、冷却、出招方式、单次 / 整组伤害和适用模式；点击“装备”才更新当前角色的武器槽。已装备卡显示“已装备”，不重复触发装备流程。武器说明中的伤害明确标注为“首领战基础伤害”，避免和普通哨兵数值混淆。

从准备页开始一次战斗后，角色与装备固定到本局结束。局内角色详情仍显示 K、被动和当前武器，但不能直接更换；暂停也不开放装备修改。需要换装备时使用“结束本局并返回准备”，主动结束不生成通关成绩。

结算页区分两个入口：

- “重试”：立即用刚才相同的角色与武器重开当前模式。
- “角色与武器”：返回准备页，可以更换后再进入任一模式。

准备页选择、预览与说明不启动游戏计时。进入场景时再创建角色、战斗状态与镜头。现有 `main.tscn`、`practice.tscn`、`boss_practice.tscn` 仍能直接通过 F6 或测试实例化：若没有显式传入出战配置，先使用本地档案的有效配置，再回退影刃与默认武器。

## 4. 更换、冷却与重试规则

| 场景 | 装备与计时规则 |
| --- | --- |
| 准备页更换 | 只改该角色的装备选择，不存在局内冷却；K 与被动不随装备改变 |
| 开始完整关卡 | 生成本局配置快照；J 在跑酷段不可释放，K 开局就绪 |
| 跑酷进入首领 | 继续同一快照；J 首次开放时就绪，K 的当前冷却与保护计时照常继承 |
| 直接首领练习 | 使用所选武器，J / K 都以新局初值就绪 |
| 局内暂停 / 看详情 | 冷却、蓄势、连发、弹体均冻结；装备只读 |
| 按 R 或结算后重试 | 复用刚才的配置快照，新建运行状态；生命、J / K 冷却与首领恢复初值 |
| 返回准备后再出战 | 重新解析当前装备，生成新的配置快照；上一局的弹体与连发队列已经释放 |
| 后续切换角色 | 准备页读取新角色各自记住的武器，不通过切换影响任何仍在进行的战斗 |

装备修改只发生在准备状态。即使未来 UI 增加了新入口，也必须由角色模块检查当前是否允许修改，不能仅靠隐藏按钮防止战斗中刷新冷却。

首轮不做局内切武器。若以后加入副武器和战斗内切换，应另设槽位，冷却归属每把武器的本局状态，切换不能取消冷却或重置连发；不能把本版“准备页更换”直接挪进暂停菜单。

## 5. 角色模块的数据边界

以下结构均已实现：

| 数据 / 模块 | 归属与职责 |
| --- | --- |
| `CharacterData` | 现有角色静态定义，保留 `active_skill` / `passive`，新增 `default_weapon_id`；不保存玩家的当前选择或冷却 |
| `WeaponData` | 角色模块内的可复用武器定义：稳定 ID、名称、说明、`allowed_character_ids` 与一个武器技能资源；允许列表为空表示通用 |
| `WeaponSkillData` | 武器行为 ID、冷却、蓄势、发射次数、间隔、伤害配置、速度与转向参数；行为由已注册的连射 / 单发实现执行 |
| `CharacterLoadout` | 某个角色的装备记录：`character_id` 与 `weapon_id`；通过角色模块执行拥有检查、兼容检查和更换 |
| `PlayerProfile` | 档案：当前选中角色、已解锁武器 ID、每名角色的装备记录；提供给准备页和存档服务 |
| `RunLoadout` | 一次出战解析得到的角色 / 武器配置快照；角色、HUD、战斗和重试统一读取它 |
| `WeaponRuntime` | 当局角色实例持有的武器冷却、蓄势、连发序号与取消标识；属于角色模块，不写回静态资源 |
| `RunnerCombat` | 读取 J / K 意图，调用相应运行实例；统一协调命中、伤害来源、击破与统计 |
| `PlayerProjectile` | 战斗模块负责实际移动与接触检测，持有发射时的伤害来源与数值，不反查准备页当前选中的武器 |
| `RopeBoss` | 只接收标准化攻击信息、应用护甲 / 弱点与死亡规则，不负责指定玩家装备或创建武器技能 |

文件按模块归属组织：

```text
scripts/characters/
├── character_data.gd                 # 扩展默认武器字段
├── character_loadout.gd
├── player_profile.gd
├── run_loadout.gd
└── weapons/
    ├── weapon_data.gd
    ├── weapon_skill_data.gd
    └── weapon_runtime.gd
data/
├── characters/shadow_runner.tres     # 默认武器 ID
└── weapons/
    ├── crescent_wheel.tres
    └── star_lance.tres
scenes/ui/character_setup.tscn
scripts/combat/player_projectile.gd
```

`ActiveSkillData` 只负责角色月蚀斩；`WeaponSkillData` 与 `WeaponRuntime` 独立负责连射 / 单发。`WeaponArt` 按武器 ID 绘制当前原型的角色挂件、卡片与 HUD 图标。所有静态资源在运行中只读，冷却属于实例。出战快照冻结影响战斗的数值与 ID，不能因另一处装备预览改变正在进行的战斗。

角色模块对外提供“列出可装备武器、查询当前装备、尝试更换、解析本局配置”四类能力。更换前检查：角色存在、武器存在、已经拥有、角色允许使用、当前处于准备状态。成功后发出装备变化事件，由准备页更新预览并请求保存；失败时保留旧装备与选择提示。

首轮两把武器允许所有已支持角色使用，兼容条件为空表示通用。未来确有角色专属武器时再配置允许角色 ID，不把“影刃只能用弦月轮”写进首领脚本。完整资源目录与初始解锁清单分开维护，新增武器资源不自动视为已经拥有；首轮明确将两把武器放进初始解锁清单。

## 6. 伤害来源与场景生命周期

攻击信息区分角色技能、武器技能和飞镖球，携带来源 ID、发射时所属角色、基础伤害和单次攻击标识。K 对普通哨兵的当前伤害 3 与首领基础伤害 24 通过伤害配置明确区分，不能让武器更换隐式改变目标倍率。

武器的每枚弹体分别结算一次，首领死亡入口统一去重。武器或飞镖球击杀也正常记入一次首领击破；伤害统计分别记录 J、K、飞镖球，用于比较装备节奏，不给多段武器额外刷连击或分数。

贯星矛蓄势、弦月轮连发期间允许继续移动和释放 K；停止、死亡、退出模式或首领死亡时取消剩余发射。取消后的队列不能在下一局接着发射。全部友方弹体随当前局释放，不能作为跨场景全局节点保留。

无效目标阶段 J 不接受释放：跑酷段、首领登场、已经击破、玩家死亡 / 停止、暂停或配置错误时，都不消耗冷却。正式交战中接受一次 J 就立即启动该武器自己的冷却；伤害延后命中不再次启动冷却。飞镖球在登场期间不生成，首领击破立即清理剩余球与自动连发。

## 7. 装备选择的保存

装备选择与这次武器功能一起持久化，不依赖后续角色养成。使用 `user://save.json` 版本化存档，当前写入：

```json
{
  "version": 1,
  "selected_character_id": "shadow_runner",
  "owned_weapon_ids": ["crescent_wheel", "star_lance"],
  "character_loadouts": {
    "shadow_runner": { "weapon_id": "crescent_wheel" }
  }
}
```

这个片段只展示角色 / 武器字段，保存时保留原文件中无关的成绩、设置和未知字段；当前只新增装备持久化，成绩与反馈偏好的完整保存仍未实现。保存稳定 ID，不保存 `.tres` 路径、场景节点、弹体、冷却或本局保护时间。当前格式版本为 1；遇到较新版本时保留原文件，本次装备只在内存生效并提示暂未保存，避免旧程序覆盖新数据。以后发生不兼容字段变更再递增版本并迁移。

首次启动或旧数据缺少这些字段时，补入影刃和两把起始武器。读取失败、武器 ID 已删除 / 未拥有 / 不兼容时，选用该角色有效的默认武器；默认也无效时由目录提供可用的起始武器，不能把无效配置带入战斗。部分字段失效不应清空其余成绩和设置。

更换成功后保存选择，重启程序恢复；采用临时文件写入后替换。保存失败时本次装备仍在内存生效，准备页提示“本次已更换，暂未保存”，按钮变为“重试保存”，无需切换武器即可再次保存。重试当前局始终读取当局快照，不因磁盘文件被修改而换成另一把武器。

## 8. 首轮交付与验收

实现顺序为：角色 / 武器定义与装备解析 → 准备页与装备保存 → 当局快照和两种武器行为 → 首领飞镖球与护甲调整 → HUD / 反馈 → 回归和实际试玩。准备页、两把可更换武器与首领输出应作为同一轮可玩的完整切片，不能只在 Boss 场景里写死一把武器完成验收。

验收覆盖：

- 准备页 A → B → A 更换，J 的名称、图标、出招形态、冷却与伤害都正确；K、被动与移动参数不变。
- 分别装备两把武器都能完成当前首领战；相同水平下时长处于相近区间，差异来自时机与节奏。180 血量与 30～45 秒目标随真实回放调整。
- 局内、暂停、蓄势 / 连发中均无法修改装备；直接调用更换入口也被状态检查拒绝。
- 更换后的选择可跨程序重启恢复；缺失字段、未知 ID 与无效装备有可玩的回退。
- R 重试与结算重试保留同一配置，准备页重新选择后再出战采用新配置；旧局弹体、蓄势和连发完全清空。
- 分别从准备页、三个场景的直接入口和测试夹具启动，装备解析一致，不要求所有调用者都经过 UI。
- 暂停、同帧 J / K、K 的保护、护甲与弱点切换、任意来源致死均遵循首领战斗设计；角色资源没有被写入临时冷却。
- 两把武器下原控制、影晶、三段跳、敌方固定方向齐射均保持既有判定；新增人物 / 武器 UI 在目标分辨率中不遮挡危险区域。

本轮验证：`test_weapons.gd` 覆盖上述边界并完成五种真实战斗回放；`test_profile_persistence.gd` 通过独立进程写入 / 读取。三渠道混用时弦月轮约 38.6 秒、贯星矛约 34.3 秒击破 180 生命首领，均无伤。1280×720 / 1600×900 图形检查覆盖准备页、两把武器的实际弹体、飞镖球与只读详情；自动回放不能代替后续真人手感调整。

后续角色复用这套装备模块，只需定义自身固有能力、默认武器和兼容条件。武器扩展先增加效果实现及数据，再进行首领对照试玩；等级、强化、副武器和战中切换各自另立设计，不与本轮的“能装备、能换、能保存、能打”混在一起。
