## 2. 视觉方向：月下雾岭，墨影与机关

沿用既有原创东方幻想方向：水墨轮廓、手绘块面、蓝灰月夜、稀疏暖金高光。环境提供空间与速度感；人物、危险和拾取物保持明确的可交互轮廓。

| 色彩 | 基准值 | 职责 |
| --- | --- | --- |
| 墨夜 | `#111827` | 暗部、衣料、界面底色 |
| 雾蓝 | `#34495E` | 中景、衣料受光面 |
| 远景灰 | `#6E7F8D` | 远山、雾层与低对比结构 |
| 月光 | `#DDE7E7` | 玩家肩颈轮廓、图标、主要文字 |
| 暖金 | `#D8B56A` | 收集物、可用技能、弱点和交互重点 |
| 朱砂 | `#B24B4B` | 机关、敌方攻击、受击与生命警示 |

月光从左上方照射。纸纹主要出现在远景和较大面板，人物和图标边缘保持干净。背景不使用红旗、红叶或密集金色灯光，以免与危险和收集物混淆。警示还应有形状、方向和动作变化，不能只靠颜色。

场景锚点已排除角色、钢索、机关、影晶和 UI，便于后续分别生成与控制。远景山形最软，中景建筑次之，交互层最清楚；高速通过的区域减少细碎树叶、瓦片和碎石纹理。

## 3. 角色与战斗对象

### 影刃

轮廓由蒙面、束发、深蓝灰紧身衣、浅月灰肩巾和小型铜月扣组成。肩颈的亮面让角色在暗背景上仍可辨识。服装不使用危险红，武器不固定烘焙在角色身体上，支持弦月轮与贯星矛独立更换。

设定图中的衣褶和飘带属于外观参考。制作实际精灵时要减少腰间细带、缩短遮挡手脚的布片，并在约 60 px 的身体显示高度检查轮廓。先以侧面动作验证，再扩充立绘。

- 上侧奔跑：脚底接触钢索，身体朝右，飘带向左。
- 下侧挂绳：双手抓住上方钢索，身体和脚自然向下，不能将整个人物上下倒置。
- 下侧跳跃键禁用；先上翻再起跳，动作设计不包含从下侧直接穿绳跳起。
- 上翻、下翻分别设计过渡；落绳、空中追加跳跃、影步和受击各有清楚姿态。
- 无敌与冷却由运行时表达，不在角色常态图片上画永久光圈。

### 武器、普通敌人和首领

弦月轮使用开口月弧和短尾迹，贯星矛使用细长枪尖和集中直线尾迹；两种弹体在小尺寸下也应能区分，保持各自实际飞行方向。

普通哨兵沿用小型翼状机关轮廓。首领“断桥机关鸢”延续木骨、暗金属、旧铜扣件与朱砂翼缘，和普通敌人共享材质语言。护甲态核心闭合且低亮，弱点态核心张开并发暖金光；半血强化增加翼缘张开和脉冲，不能只给全身换红色。

首领、武器与特效的专门设定图列入下一阶段，本轮没有将这些对象标记为美术完成。

## 4. 玩法与图片的尺寸约束

以现有 1280×720 设计坐标为准。美术接入应适应当前判定，不能为了匹配概念图改变障碍、角色或落绳规则。

| 对象 | 当前约束 | 美术要求 |
| --- | --- | --- |
| 钢索 | 单根水平线，`Y=520` | 实际游玩保持水平，不增加第二根可被误认为路线的绳索 |
| 玩家 | 身体胶囊约 36×60，上下侧身体中心距钢索 34 | 透明留白、飘带和武器不计入身体判定；贴图原点与身体中心对齐 |
| 上下侧身位 | 上侧中心 `Y=486`，下侧中心 `Y=554` | 下侧手部可由贴图延伸至绳索；视觉接触点与实际身位对应 |
| 机关 | 按关卡配置单侧生效 | 上侧机关的危险尖端只朝上；下侧只朝下，对侧必须看起来能通过 |
| 普通影晶 | 对应侧角色身体高度 | 生成独立晶体，由关卡摆放；不把概念图中的装饰排列写进背景 |
| 预警 | 现有独立计时和固定弹道 | 装饰不能长得像预警线或遮住安全弹道间隙 |
| 首领 | 中央受击矩形约 104×112，翼幅更宽 | 身体受击区清楚，翼缘装饰不能暗示与实际不同的碰撞范围 |

当前 UI 概念图仍有图像生成造成的位置与比例偏差，例如绳索高度、按钮尺寸和左右边距。它只定义外观关系；接入时按上表、`ScreenLayout` 安全区和实际角色身位重新布局。山谷锚点也是完整构图，尚未制作可横向循环的独立图层，不能当作无缝贴图使用。

## 5. 界面语言

面板使用低纹理墨色底、细暖金边和月白功能图形，装饰不侵入文字与按钮有效区域。保持玩家已确认的两左三右玩法按键：左侧独立跳跃、同键上下翻绳；右侧影步、武器、忍术。

- 跳跃图形与翻绳图形必须不同。下侧时跳跃变灰，并保持真实禁用状态；翻绳按钮根据状态表达上翻、下翻或快速下落。
- 按键至少提供可用、按下、禁用、冷却四种视觉状态，不能靠替换文字维持反馈。
- 冷却环、动态数值、名称、生命、计时和进度由 Godot 节点绘制；不烘焙进图片。
- 触摸按钮沿用约 96×96 的设计目标，受安全区调整；按钮在上下侧角色身位下方，并保持间隔。
- 顶部集中生命、影晶、进度和设置；首领信息放在上方空位。角色详情、统计等长信息仍放在独立面板，给翻绳与弹道留出空间。
- 准备页、设置和结算页复用同一套面板与按钮素材。正式界面图片不包含版本号、快捷键、标题和不可修改的中文。

## 6. 资源拆分与制作顺序

下表是生产规格草案。当前 P1 界面已从 PSD 整理 10 张候选 PNG，保留原始尺寸（约 100～180 px），供 96×96 按钮下采样预览；未将它们放大为 256×256。使用方法见 [UI 组件包](../art/layered/ui_touch_v02_candidate/README.md)。其他生产资源尚未完成，第一批优先形成能在真实速度下检查的美术切片。

| 批次 | 资源 | 交付建议 | 验收重点 |
| --- | --- | --- | --- |
| P1 场景 | 天空 / 月亮、远山、中景断桥、近景装饰 | 分层 PNG，主图层建议 2048×1024；需要循环的图层单独生成并检查接缝 | 横向滚动、层级对比、上下安全路线 |
| P1 玩家 | 侧面站姿、奔跑、下侧挂绳、跳跃 / 下落 | 独立透明帧，建议 256×256 统一画布，再按一致原点组图集 | 60 px 身体轮廓、脚和手的贴绳点、逐帧稳定 |
| P1 交互 | 钢索段、上下机关、影晶 | 独立透明 PNG，建议 128～256 px 原始画布 | 单侧危险、收集高度、拼接与缩放边缘 |
| P1 界面 | 两左三右图标、通用按钮、HUD 面板 | 图标 256×256，透明；面板保留可九宫格拉伸的低纹理中心 | 小尺寸辨认、禁用、按下与冷却 |
| P2 动作 | 上下翻绳、追加跳跃、落绳、影步、受击、死亡 | 与 P1 同画布、原点和角色比例；帧数在动作回放后确定 | 切换不抖动，不用画面动画延迟改变判定 |
| P2 战斗 | 两把武器、飞镖球、哨兵、首领各状态 | 按对象独立图集，建议单图集不超过 2048×2048 | 护甲 / 弱点 / 强化、实际弹体轨迹 |
| P2 特效 | 月蚀斩、保护、命中、拾取、首领强化 | 透明特效或短帧序列，光效与主体分开 | 不遮盖预警，不增加伪危险，不破坏现有容量限制 |
| P3 菜单 | 角色准备、设置、暂停、结算、正式图标 | 复用通用主题；立绘与 UI 底图分离 | 三种模式、触摸全流程、宽屏与安全区 |

角色主动画可先用 6～8 帧奔跑、4 帧挂绳建立动作节奏，具体数量在小尺寸回放后确定。透明精灵不能从本轮带纸底的角色设定图直接抠取后宣称完成动画。

## 7. 下一阶段验收

1. 先评审场景氛围、影刃外观和界面语言，再固定为生产参考；当前三张均保留待评审标记。
2. 用透明玩家、分层背景、机关、影晶和按钮完成 P1，在 1280×720 及宽屏触屏预览中回放真实路线。
3. 同时检查上侧奔跑、下侧挂绳、跳跃和空中快速落绳；两侧危险必须在画面和判定上对应。
4. 检查 PNG 透明边缘、统一原点、纹理尺寸、循环接缝、缩小后的图形辨识度；概念图不代替这些检查。
5. 接入后运行相关逻辑回归并检查实际画面；Android 实机帧率和触摸验收仍单独完成。
