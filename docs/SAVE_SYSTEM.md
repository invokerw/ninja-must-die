# 成绩、设置与存档

> 版本：0.3 · 2026-11-05 · 三星、通关奖励与存档事务已接入；商店消费待实现

## 玩家看到的行为

正式主线成功通关后，结算显示本局星级、历史最高星级、独立无伤印、分数、收集和受击。地图优先显示最高星级与是否已获无伤印；详情可切换“全角色最高 / 当前角色”。收集与受击明细来自最高分的同一局，最快时间另存，不拼接不同局的数据。

```text
P = 1000 + floor(1000 × collected / total) + max(0, 1000 - 150 × damage_count)
1 星：P < 2200；2 星：2200 ≤ P < 2600；3 星：P ≥ 2600
无伤印：damage_count == 0，与星级分别记录
```

计算使用整数除法，不四舍五入。40/50 影晶、受击 1 次得 2650 分三星；50/50、受击 2 次得 2700 分三星。时间、击破和连击只显示，不影响主线星级。普通影晶总数必须大于零，非法统计拒绝写入。当前尚无护身符 / 回春药，后续补给接入须沿用有效受击计数，不能靠恢复生命洗掉受击。

新纪录分别保存最高分单局、最快单局和首次无伤单局的完整快照，包含收集 / 总数、受击、用时、角色、武器、成长、道具、计分规则、出战规则、游戏版本和 UTC 完成时间。地图纪录与最高分的桌面悬停提示可查看出战配置、首次无伤时间及保留的旧成绩；移动端专门的完整快照详情展示仍待后续 UI 切片。最高星级不因较差的后续通关下降，首次无伤信息不被重复取得覆盖。

完整关卡、跑酷练习和首领练习按模式隔离。练习保留旧版用时 / 分数 / 评级统计，不写主线星级、不解锁主线、不发奖励；首领练习只显示用时和完成次数。失败、中途重试、主动返回和加载失败不生成通关纪录。每局创建稳定的随机 `run_id`；暂停保持 ID，重试创建新 ID。重复终点信号与重放已存 ID 都不增加次数。

保存失败时，本次装备、成绩和设置仍在内存生效。准备页、设置面板与结算页提供“重试保存”，按钮只重试持久化，不再计算或记录一次通关。奖励待保存时，余额与领取结果标记为仅内存有效，正式重试和新的正式挑战会被阻止；重试保存成功后恢复。免费练习仍可进入，不增加新的奖励事务。结算“奖励明细”可触摸切换，显示本次通关、收集、首通、新星、首次无伤和里程碑金额。成长与商店购买、补给库存仍待后续切片。

## 通关奖励

| 奖励 | 铜钱 | 去重范围 |
| --- | ---: | --- |
| 起始赠送 | 120 | 每份档案一次 |
| 正式通关 | 60 | 每个新成功 run_id 一次 |
| 普通影晶收集 | `floor(20 × collected / total)` | 同一 run_id 一次 |
| 首次通关 | 160 | 稳定关卡首通 ID 一次 |
| 新星 | 每颗 40 | 每关只支付未领取的星数差额 |
| 首次无伤印 | 30 | 每关一次，独立于角色 / 星级 |
| 章节累计 6 / 10 / 15 星 | 120 / 200 / 300 | 每个稳定章节里程碑 ID 一次 |

例如 40/50、受击 2 次首次二星通关奖励 316，余额从 120 变成 436；同样表现再次通关只得 76。提高至 45/50、受击 1 次三星得 118（含新增一星 40）；后来首次无伤另得 30。切换角色、重试保存、重复终点、重复单局 ID 都不重领首通、新星或无伤奖励。

`RewardService` 只接受标记成功、可复算、属于已知关卡的正式结果。它在独立草稿中生成新成绩、钱包、领取账本、角色与下一关所有权，再由 `PlayerProfile` 一次提交给 `ProfileStore`。UI 读取摘要副本，动画和按钮不再发钱。角色解锁条件读取注册表资源：第一关首通得到岚织所有权；正式准备页的角色选择界面、岚织专属忍术仍未接入。

目前目录只有两关，正式流程能达到章节 6 星。10 / 15 星的铜钱规则已有专项覆盖，后续关卡未制作；15 星外观奖励、章节无伤集齐外观、成长和消费尚未实现。本切片为内部开发闭环，尚不满足包含可消费用途的正式发布边界。

## 格式与迁移

主文件为 Godot `user://save.json`，当前 `ProfileStore.VERSION = 3`。v3 引入真实余额和奖励账本，阻止旧版 v2 程序只写成绩却遗漏经济状态。

| 字段 | 当前职责 |
| --- | --- |
| `selected_character_id` / `owned_weapon_ids` / `character_loadouts` | 保留角色选择与装备 |
| `settings` | 音效、粒子、震动、闪光四个布尔开关；保留未知开关 |
| `run_records` | 旧版正式纪录与所有练习纪录，继续保留原等级 / 分数 |
| `level_progress[canonical_level_id].overall` | 新主线全角色星级、最高分、最快、最佳收集、无伤印及新规则完成次数 |
| `level_progress[canonical_level_id].characters[character_id]` | 各角色同结构纪录 |
| `level_progress[canonical_level_id].completed_run_ids` | 已记录的单局 ID，随成绩一起写入，用于重载后去重 |
| `coins` | 0～10 亿的整数铜钱余额；UI 只读 |
| `reward_ledger.grants` | 起始、首通、首次无伤和章节里程碑稳定 ID |
| `reward_ledger.paid_stars` | 每个稳定关卡 ID 已领取星数 |
| `reward_ledger.runs` | 成功单局的金额分解、余额与解锁摘要；历史迁入 ID 仅保留迁入标记 |
| `unlocked_level_ids` / `unlocked_character_ids` | 与成绩、领取账本一起更新的所有权；保留未知 ID |
| `pending_transaction` | 已保存文件固定为 null；运行中待保存草稿由档案持有 |

每条新纪录持有 `best_score_snapshot`、`fastest_snapshot`、`flawless_snapshot`（尚未无伤时为空）。快照保存单局原始统计，读取时复算分数 / 星级，拒绝非有限数、非法计数、不一致的星级或跨关引用。失效聚合纪录不抹除有效的相邻模式 / 角色纪录；后续合法单局可重建该聚合。保存保留未知顶层、关卡条目、角色条目和纪录扩展字段。

v1 / v2 档案读取后先在内存中构造一次迁移草稿，下次正常保存或首次正式出战前提交为 v3：

- 原 `run_records`、装备、设置和未知字段原样保留。缺失新字段视为空纪录；不要求重置存档。
- 旧分数与评级不转换成星级或无伤印，也不归到某个角色。地图显示“旧版 S · 星级待挑战”等提示。
- 旧完整关确有通关纪录时继续满足第一关前置；旧练习纪录不能解锁第二关。迁移同时开放第二关与岚织所有权，并用相同的首通 ID 补发一次 160 铜钱；旧练习纪录不能享受这些补发。
- `fog_ridge_60s` 与目录稳定 ID 都能查询同一新主线纪录；旧桶保持原 ID。新旧最高分单独比较，旧分数不会压住新规则的 3000 分上限。
- 新规则完成次数与旧通关次数分开保存；地图悬停可查看旧版次数和最快时间。
- 每份旧档补一次起始 120；v2 已有可验证星级 / 无伤印的，补相应的一次性星级、无伤和里程碑奖励。已记录 run_id 迁入账本，不能通过重放旧结果再领取。旧累计完成次数不补基础或收集奖励。
- 保留未知顶层、账本扩展、关卡与角色条目；余额、账本结构或回执字段损坏会触发整份备份恢复，不单独清零钱包后继续发奖。
- 遇到较新顶层版本，只读取能理解的内容，禁止写回主文件和备份；新变化仅在内存生效并提示未保存。

## 写入、备份与恢复

1. 将当前整份档案写入 `save.json.tmp`，刷新并检查写入结果。
2. 把主文件上一份有效 JSON 写入临时备份，再替换 `save.json.bak`。首次保存时备份与主文件内容一致。
3. 用完整临时文件替换主文件；任一步失败都会保留内存更改并显示可重试状态。

星级、单局快照、余额、所有权和领取账本在同一文件代际内提交。启动优先读取主文件；主文件不存在、JSON 不完整或版本字段失效时尝试 `.bak`。恢复可能回到前一次成功保存，界面提示“已恢复上次保存”。恢复保存不使用损坏主文件覆盖有效备份，并把损坏原件保留为一份 `save.json.corrupt`。

保存失败保留一个不可重算的待保存草稿；改变声音或装备的后续保存也会尝试提交同一草稿。失败后不叠加新的正式奖励事务，既有事务提交前不开始新的正式局。异常退出只保留最近一次成功落盘的完整代际，未落盘的本局奖励不会在重启时被补发。

当前仍是本机单进程档案，不包含云同步、并发进程合并或局内断点续玩。准备页 / 暂停 / 结算的反馈设置沿用同一保存入口。
