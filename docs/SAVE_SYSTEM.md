# 成绩、设置与存档

> 版本：0.1 · 日期：2026-10-25 · 对应游戏设计 v0.12，已实现

## 玩家看到的行为

准备页的完整关卡、首领练习、跑酷练习入口下显示各自历史最佳。完整关卡与跑酷练习展示最快时间、最高评级、最高分、最佳收集和完成次数，各项纪录独立统计；首领练习只展示最快时间与完成次数，不作为整关评级。没有纪录时显示首次通关提示。

成功完成一个模式后自动保存一次，重复终点信号不会增加次数。失败、中途重试或主动返回准备不生成通关纪录。重试不清空历史最佳；出战快照与装备规则沿用 v0.11。

准备页和局内共用“设置 F2”面板，音效、粒子、画面震动、冲击闪光独立保存。M 静音与按钮使用相同入口，暂停 / 结算时也可操作。开关立即作用于当前声音和效果，保存成功后下次启动恢复。

保存失败时，本次装备、成绩和设置在内存中继续生效。准备页、设置面板和结算页提供“重试保存”，再次保存不会新增一次通关；下次正常保存也会一起写入所有待保存内容。结算显示“成绩已保存”或“暂未保存，可重试”。

## 格式与兼容

主文件为 Godot `user://save.json`。新增字段属于兼容扩展，继续使用版本 1；旧版装备存档缺失成绩或设置时采用空纪录和默认开启，不要求迁移或重置装备。

```json
{
  "version": 1,
  "selected_character_id": "shadow_runner",
  "owned_weapon_ids": ["crescent_wheel", "star_lance"],
  "character_loadouts": {
    "shadow_runner": { "weapon_id": "star_lance" }
  },
  "settings": {
    "sound": true,
    "particles": true,
    "shake": false,
    "flash": true
  },
  "run_records": {
    "fog_ridge_60s": {
      "full": {
        "best_time": 98.4,
        "best_rank": "S",
        "best_score": 4240,
        "best_collected": 50,
        "collectible_total": 50,
        "completions": 1
      }
    }
  }
}
```

另外两种模式使用同级 `parkour_practice`、`boss_practice`。不同关卡使用不同 ID。最快时间取较小值，评级按 C / B / A / S 比较，最高分取较大值；最佳收集先比较比例，相同比例再比较数量，并保留对应总数。示例中的各项最佳可能来自不同次通关。

设置仅接受布尔值，不把字符串 `"false"` 或数字 0 当成合法开关。成绩校验有限正用时、已知评级、非负整数统计、收集数不超过总数；一个模式的失效纪录不会使其他模式失效。保存保留未知顶层、设置与角色装备字段，以及其他关卡的数据。旧规划的 `best_times` 等字段如已存在会原样保留，当前运行纪录统一使用带模式的 `run_records`。

## 写入、备份与恢复

1. 将当前档案写入 `save.json.tmp`，刷新并检查写入结果。
2. 把主文件上一份有效 JSON 写入临时备份，再替换 `save.json.bak`。首次保存时备份与主文件内容一致。
3. 用完整临时文件替换主文件；任一步失败都会保留内存更改并显示可重试状态。

启动优先读取主文件；主文件不存在、JSON 不完整或版本字段失效时尝试 `.bak`。恢复备份可能回到前一次成功保存的状态，界面提示“已恢复上次保存”。主文件和备份均失效时使用默认配置。恢复保存不会用损坏主文件覆盖有效备份，并将损坏原件保留为一份 `save.json.corrupt`。

遇到较新格式时只读取能理解的内容，阻止写回，保留主文件和备份；本次修改仍可用于本次运行。当前是本机单进程存档，不包含云同步、多个同时运行进程的合并或进行中断点续玩。

## 模块与验证

`PlayerProfile` 持有共享档案、装备、反馈设置与待保存状态；`RunHistory` 负责模式分区、校验与最佳成绩聚合；`ProfileStore` 负责 JSON 读取、临时写入、备份和恢复。`main.gd` 只在成功结算入口提交成绩，UI 通过同一档案保存，反馈面板负责即时应用效果。

`tests/test_save.gd` 验证最佳纪录分别更新、模式和关卡隔离、错误类型回退、旧字段保留、较新版本保护、主文件损坏 / 缺失恢复、保存失败重试，以及实际终点、首领击破、死亡与返回准备的记录边界。`tests/test_profile_persistence.gd` 通过两个独立进程验证装备、四个反馈开关与不同模式的纪录恢复。

所有回归通过 `TestProfileScope` 使用 `.godot/` 下独立测试档案，结束时释放并清理，不写玩家的 `user://save.json`。本轮九套回归通过；1280×720 / 1600×900 图形检查覆盖空纪录、历史最佳、设置、失败重试与真实首领结算。
