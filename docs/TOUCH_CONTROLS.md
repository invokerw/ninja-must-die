# 移动端触屏操作

> v0.14 · 2026-10-26 更新左侧按键 · 触屏原型已实现，Android 实机与性能验收待完成

## 使用

移动设备或有触摸屏的设备自动显示局内触屏按钮。桌面按 `F3` 切换触屏预览，可用鼠标点按；预览模式在重试、返回准备和再次出战之间保留，不写入玩家存档。也可使用启动参数：

```powershell
& $godotPath --path . -- --touch-controls
```

| 位置 | 按钮 | 行为 |
| --- | --- | --- |
| 左下 | 跳跃 | 独立跳跃键；钢索上侧起跳，空中按角色额度追加跳跃；下侧置灰禁用，需先翻回上侧 |
| 左下 | 下翻 / 上翻 / 快速下落 | 同一个翻绳键：钢索上方按下翻到下方，下方按下翻回上方，空中按下立即快速落绳 |
| 右下 | 影步 | 沿用原冲刺、保护与冷却 |
| 右下 | 当前武器名称 | 沿用 J，读取本局装备、冷却及首领交战限制 |
| 右下 | 当前忍术名称 | 沿用 K，显示真实冷却与就绪状态 |
| 顶部 | 暂停 / 继续 | 冻结或恢复本局；暂停面板也提供继续、重试和返回准备按钮 |

准备页换装、装备保存、三个模式入口、设置、只读角色详情、暂停、重试和返回准备均使用现有 `Control` 交互，可全程触摸操作。设置面板增加关闭按钮；触屏模式下局内打开设置会暂停，关闭后恢复进入面板前的暂停状态。打开角色详情时先关闭设置，避免叠加暂停状态。

## 输入与生命周期

每根手指按触摸 `index` 绑定起始按钮。两根手指按同一动作时，最后一根松开才解除保持；不同手指可以同时翻绳、使用武器和忍术。手指滑出按钮会解除该动作，滑到相邻按钮不自动施放，需抬起后重新点按。系统取消触摸也会解除保持。

长按只产生一次新的按下。冷却期间的点按不会排队到就绪后自动释放；正常点按即使在两个物理帧之间完成，也会在下一次物理更新被读取一次。影步、武器、忍术继续使用现有冷却、保护、弹体与伤害结算，触屏不直接调用攻击或修改 Boss 生命。

跳跃键始终显示“跳跃”，在钢索下侧置灰禁用，不会兼作上翻或手动抓绳；下侧点按或长按不排队补跳，先翻回上侧后需重新点按才起跳；翻绳键的文字随实际状态显示“下翻”“上翻”或“快速下落”。空中短点按翻绳即可转为快速下落，不需要持续按住；落绳后停在上侧，继续长按不会再次翻到下侧。两个左侧按钮同帧点按时优先翻绳，不排队补跳。键盘 W / ↑ / Space 和 S / ↓ 保留原有操作。

暂停、打开详情或设置、死亡、结算、失焦、应用进入后台、布局变化和切换场景都会清除触摸保持及待处理的点按。触屏模式失焦或进入后台同时暂停，回到应用后需主动继续。键盘与触摸独立，释放其中一方不会误释放另一方。

`RunInput` 是每个玩家实例独有的输入桥接，组合现有 InputMap 动作与触摸动作，供 `PlayerController` 和 `RunnerCombat` 在同一个物理更新中读取。左侧使用独立的 `jump_only` 与 `rope_flip` 触摸动作，右侧沿用现有战斗动作；移动仍由角色的物理更新处理。触屏状态不保存在静态单例或玩家档案中。`TouchControls` 负责触点、按钮显示和安全区布局，`main.gd` 处理暂停与场景导航。普通菜单继续使用 Godot 的触摸转鼠标机制，玩法按钮忽略该机制生成的鼠标事件，防止同一触摸触发两次。

## 屏幕布局

移动端使用自动横屏方向和扩展画布；桌面普通模式保持原比例，触屏预览可展开宽屏画布。HUD、准备页和菜单以 1280×720 为设计基准，居中等比放入安全区域；触屏按钮分布在安全区域两侧，世界相机继续独立滚动。

默认玩法按钮 96×96、间隔 16 个设计单位。读取系统安全区后调整位置和尺寸，为下侧角色碰撞身位留出空间；屏幕变化会解除旧坐标上的触点。局内段落提示移到钢索上方，避免与底部按钮重叠。所有按钮仍使用当前原型的代码占位视觉，正式按钮图片按项目美术流程另行制作。

实现使用 [Godot 屏幕触摸事件](https://docs.godotengine.org/en/stable/classes/class_inputeventscreentouch.html) 的独立触摸索引，以及 [DisplayServer 的显示安全区域](https://docs.godotengine.org/en/stable/classes/class_displayserver.html#class-displayserver-method-get-display-safe-area)。
