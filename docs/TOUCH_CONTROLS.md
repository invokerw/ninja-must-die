# 移动端触屏操作

> 2026-11-09 更新通用战斗 HUD · 触屏输入已实现，Android 实机与性能验收待完成

## 使用

移动设备或有触摸屏的设备自动显示局内触屏按钮。桌面按 `F3` 切换触屏预览，可用鼠标点按；预览模式在重试、返回准备和再次出战之间保留，不写入玩家存档。也可使用启动参数：

```powershell
& $godotPath --path . -- --touch-controls
```

普通桌面模式显示同一套只读动作状态和键盘提示，仍由键盘输入；F3 才启用触点 / 鼠标的玩法按钮。桌面右上暂停入口可直接点击。

| 位置 | 按钮 | 行为 |
| --- | --- | --- |
| 右下 | 跳跃 | 独立跳跃键；钢索上侧起跳，下侧回到上侧，空中追加一次基础二段跳 |
| 左下 | 下翻 / 上翻 / 快速下落 | 同一个翻绳键：钢索上方按下翻到下方，下方按下翻回上方，空中按下立即快速落绳 |
| 右下 | 当前身法名称 | 踏影：二段跳后点按第三跳；御风：下降时按住，累计 1.2 秒；雷闪：点按短冲，6 秒冷却 |
| 右下 | 当前武器名称 | 沿用 J，读取本局装备、冷却及首领交战限制 |
| 右下 | 当前忍术名称 | 沿用 K，显示真实冷却与就绪状态 |
| 顶部 | 暂停 / 继续 | 冻结或恢复本局；暂停面板也提供继续、重试和返回准备按钮 |

准备页换装、装备保存、三个模式入口、设置、暂停、重试和返回准备均使用现有 `Control` 交互，可全程触摸操作。设置面板增加关闭按钮；局内设置从暂停界面的“设置”进入，关闭后恢复暂停界面。暂停界面统一显示技能与武器说明。

暂停与结算现在共用 `UIRunPanel`，长说明 / 奖励可滚动，操作与存档状态固定；设置子窗打开时不响应后台触屏暂停。布局、输入与验收边界见[通用 UI 第四批](UI_DESIGN_SYSTEM.md#13-第四批暂停与结算通用面板)。

## 输入与生命周期

每根手指按触摸 `index` 绑定起始按钮。两根手指按同一动作时，最后一根松开才解除保持；不同手指可以同时翻绳、使用武器和忍术。手指滑出按钮会解除该动作，滑到相邻按钮不自动施放，需抬起后重新点按。系统取消触摸也会解除保持。

点按型动作长按只产生一次新的按下；御风按住持续生效，松开保留本次离绳的剩余时长。冷却期间的点按不会排队到就绪后自动释放；正常点按即使在两个物理帧之间完成，也会在下一次物理更新被读取一次。身法、武器、忍术使用各自运行时的冷却、保护、弹体与伤害结算，触屏不直接调用攻击或修改 Boss 生命。

跳跃键始终显示“跳跃”，在钢索上侧起跳、下侧回到上侧、空中追加一次基础二段跳；翻绳键的文字随实际状态显示“下翻”“上翻”或“快速下落”。空中短点按翻绳即可转为快速下落，不需要持续按住；落绳后停在上侧，继续长按不会再次翻到下侧。跳跃和翻绳同帧点按时优先翻绳，不排队补跳。键盘 W / ↑ / Space 和 S / ↓ 保留原有操作。

暂停、打开设置、死亡、结算、失焦、应用进入后台、布局变化和切换场景都会清除触摸保持及待处理的点按。触屏模式失焦或进入后台同时暂停，回到应用后需主动继续。键盘与触摸独立，释放其中一方不会误释放另一方。

`RunInput` 是每个玩家实例独有的输入桥接，组合现有 InputMap 动作与触摸动作，供 `PlayerController` 和 `RunnerCombat` 在同一个物理更新中读取。左侧使用独立的 `rope_flip` 触摸动作，右侧使用 `jump_only`、`mobility` 和现有战斗动作；移动仍由角色的物理更新处理。运行时右上角色、技能和武器说明收起，底部按钮自身显示名称与冷却，暂停遮罩提供忍术、身法和武器技能介绍。触屏状态不保存在静态单例或玩家档案中。`TouchControls` 负责触点、按钮显示和安全区布局，`main.gd` 处理暂停与场景导航。普通菜单继续使用 Godot 的触摸转鼠标机制，玩法按钮忽略该机制生成的鼠标事件，防止同一触摸触发两次。

影刃的第三跳只接受独立身法边沿，同帧“第二跳 + 踏影”只执行第二跳。御风在上升段不消耗时长，下降后开始；快落、受伤或落绳取消滑翔。暂停与失焦清理触摸和键盘的按住状态，恢复后必须重新按住。雷闪期间的翻绳 / 快落意图在短冲结束后执行。旧 `dash` 仅作为一个版本的输入别名，调用同一角色身法。

## 屏幕布局

移动端使用自动横屏方向和扩展画布；桌面普通模式保持原比例，触屏预览可展开宽屏画布。HUD、准备页和菜单以 1280×720 为设计基准，居中等比放入安全区域；触屏按钮分布在安全区域两侧，世界相机继续独立滚动。

默认玩法按钮 96×96、间隔 16 个设计单位。按钮整体离开底边，右侧四键采用两层错位的三角布局，读取系统安全区后调整位置和尺寸，并为下侧角色碰撞身位留出空间；屏幕变化会解除旧坐标上的触点。局内段落提示移到钢索上方，避免与底部按钮重叠。

2026-11-09 默认 `PaintedTouchControls` 已改用原生 `UICombatAction / UIRadialMeter`，共用 `UITokens / PaintedTheme`，继续复用 `TouchControls` 的输入和状态规则。圆内状态、圆外名称、按下 / 禁用边线彼此分离；御风显示剩余额度，雷闪显示冷却，武器图读取当局装备，不再叠加遮挡图标的小牌。顶部 `UIBattleHUD` 负责生命 / 路线、首领、威胁和被动补给；完整范围与证据见[战斗 HUD 任务卡](../art/validation/ui/battle_hud/v01/README.md)。下述独立场景继续保留候选图层评审用途。

## UI 美术候选预览

打开 `scenes/art/ui_touch_preview.tscn` 按 F6，可在真实玩法中检查五个图像按钮，并通过预览入口切到首领战。图片来自 UI v02 PSD 的十张独立透明图层；按下缩放、禁用变暗、方向提示、冷却环和数值由 Godot 绘制。标题文字位于按钮图形下方，并受底部安全区约束。按钮的输入区域、状态门控和多指逻辑复用 `TouchControls`。

候选渲染通过 `tests/test_ui_art_preview.gd` 复用全套触摸行为回归，并增加较大底部安全区的文字边界检查；历史上已完成 1280×720 / 1600×720 图形检查。独立场景不记录通关成绩；正式导出排除原候选目录。默认游戏的圆底和多数动作图形现由通用控件绘制，原位图与历史证据保留。候选文字 / 状态已适配新组件，用户视觉验收和 Android 实机仍待进行，详见 [组件说明](../art/layered/ui_touch_v02_candidate/README.md)。

实现使用 [Godot 屏幕触摸事件](https://docs.godotengine.org/en/stable/classes/class_inputeventscreentouch.html) 的独立触摸索引，以及 [DisplayServer 的显示安全区域](https://docs.godotengine.org/en/stable/classes/class_displayserver.html#class-displayserver-method-get-display-safe-area)。
