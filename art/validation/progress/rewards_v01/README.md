# 通关奖励与存档事务 · 2026-11-05

当前状态：功能与助手截图检查完成；用户视觉、手感与 Android 实机统一待验收。延续现有准备页、地图和结算面板，仅新增动态余额、待保存提示与奖励明细切换，没有新增贴图设计或独立测试场景。

## 功能与入口

F5 → 关卡选择 → 开始挑战 → 成功完成。结算显示本次铜钱、余额和新增解锁，点击“奖励明细”查看基础 / 收集 / 首通 / 新星 / 首次无伤 / 章节星数金额，点击“返回成绩”切回。准备页和地图显示同一份钱包。

`RewardService` 在独立草稿内计算，`PlayerProfile` 提交整份 v3 档案：成绩、余额、稳定领取 ID、单局回执、角色与关卡所有权一同保存。重复终点与已结算 run_id 不再发奖。失败或练习不发铜钱。

保存失败时结算标记“奖励仅在内存中”，显示重试保存；离开结算后准备页、地图也保留余额待保存标记。正式重试 / 新正式局暂不开始，免费练习可进入且保留常驻提醒。保存按钮只重写原草稿，不重新计算奖励。

## 回归与边界

奖励事务专项要求退出 0 且输出 `REWARD_TRANSACTIONS_PASS`，覆盖：

- 起始赠送、首通、重复通关、升星差额、跨角色无伤去重和章节里程碑。
- v1 旧完整关补一次首通、不造星；v2 只补已有一次性权益、不追溯重复奖励，旧单局 ID 不能重放。
- 临时写入 / 备份 / 主文件替换三处故障：旧文件不部分更新、内存保留唯一草稿、新正式事务被阻止、重试不重算。
- 钱包 / 回执错误类型、负数、非有限数、越界校验，整份备份恢复及较新版本保护；未知账本 / 回执 / 所有权扩展保留。
- 实际正式 / 练习结算、重复完成、触摸奖励明细、UI 待保存状态及免费练习常驻提示。

跨进程 `test_profile_persistence` 另验证钱包、奖励回执、成绩与装备一起恢复，以及已结算单局的重载去重。日志位于 `/tmp/ninja-rewards-final-*.log`；图形日志为 `/tmp/ninja-rewards-capture.log`。本机无显示引擎仍会输出既有 `get_system_ca_certificates` 诊断，检查脚本错误与 PASS 独立进行。远端 CI 与 Android 实机未执行。

本地 17 套 GDScript 回归串行退出 0 并获得对应 PASS，5 项 Python 导出测试通过，跨进程写入 / 读取分别输出 `PROFILE_WRITE_PASS` / `PROFILE_RELOAD_PASS`。最后的 HUD 常驻提示改动后又串行复测奖励、成绩、存档、触屏、UI 预览及关卡选择套件，并更新图形证据。未发现新增脚本错误或断言失败。Godot 编辑器导入生成了新增脚本 UID，退出 0；退出时仍有 Android SDK / ADB 的 `EditorSettings not instantiated` 诊断，不将此视为 Android 环境验收。

当前正式目录只有两关，实际可达 6 星里程碑；10 / 15 星铜钱规则通过独立验证。章节外观、完整角色选择、专属忍术、成长、商店购买、库存扣除和补给使用尚未实现，不能将此切片标为整个经济系统或正式发布闭环完成。截图与记录保留为后续统一验收证据，两个正式导出预设均排除 `art/validation/*`。
